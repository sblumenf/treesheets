    Cell formatting & Zoom
      (14) Text in a cell is akin to a single paragraph. It is split up in lines automatically depending on the column width of whatever column it is in. How wide the columns should be depends on how you prefer to structure your TreeSheet overall. You can see the column width in the status bar (for the column the mouse is over). Make sure this cell is selected, and then hold ALT and roll the mousewheel to see what happens (or ALT+PGUP/PGDN). This cell should be reformatted automatically, as well as other cells in this column, and any grids inside this column. Note that the column width specifies the maximum number of characters per line, so it won't make a grid wider once every cell is on a single line.
        On some Mac keyboards, PGUP/PGDN is emulated with FN+UP/DOWN. Also, the scrollwheel is instead a swipe on the trackpad (or magic mouse).
      (15) A more powerful option to change the space a cell takes up on screen (good for indicating the relative importance of something) is to change the text size. Select this cell, hold SHIFT and roll the mousewheel (or SHIFT+PGUP/PGDN).
      (16) Notice how if you keep making it smaller, eventually text will be rendered as individual pixels. This may seem useless, but is actually a neat way of information management that replaces folding/unfolding of hierarchies so prevalent in other applications.
      (17) For example, this cell contains a tiny grid. Select this cell, then hold CTRL and roll the mouse wheel forward 3x to zoom into this cell (or CTRL+PGUP/PGDN).
        (18) You couldn't read this text before, but now you can!
        (19) When you zoom in, TreeSheets sets the base text size to the average size of the top level grid shown. When you change the text size with SHIFT+scrollwheel, you change the relative size of text. That means it depends on the zoom level how big that text appears. This may sound complicated, but the net effect is that you can make text really small yet see more of it when you zoom in.
        (20) The idea is that you use small sub grids like this one to store information (such as a todo list for a specific project) that you want to be available in your overal TreeSheet, but you don't want it to take up space. Reading or editing it is always just a flick of the mousewheel away.
        (21) Also, setting text size is something you have to generally do only once, whereas tree folding/unfolding or scrolling as you end up doing in other applications is something you do every time you want to view the information. TreeSheets makes navigating large amounts of information less of a chore, and easier to overview (the pixel sized text still gives an impression of how much information is contained inside the cell, and the structure of it).
        (22) To make this text readable at the top level again, select cells (18..23) (not 17), zoom out twice (mousewheel back), and then SHIFT+mousewheel forward until this becomes readable again.
        (23) If you now want to make this smaller, select the same cells, and use SHIFT+mousewheel backward to reduce the size.
        (24) Notice the greyed out text you see above the header text when you are zoomed in? This is called the context, and helps you remember what part of the treesheet you zoomed in to.

    Images & Styles
      Add Images to cells to make your document clearer. Images appear in front of the text of that cell. Put an image in its own cell for maximum flexibility. Try adding a (small) image to any cell above (menu Edit/Add Image, or pick one from the image drop down on the toolbar). 
        Images are stored inside a document (.cts) file, meaning if you move a file around, you will never lose the images. If you use an image multiple times in a document, only one copy is stored.
        If you'd like to refer to large images in a treesheet, and they would be too clumsy to have inside the sheet, you can also simply put the images in the same folder as the .cts, and simply put just their name in a cell. You can then use Edit/Open File (F4) to view them.
          You can refer to any file type this way
          to conveniently add new file links, just drag and drop non-image files onto cells
      Make a cell bold, or italic, or both! Try CTRL+b or CTRL+i on some cells, both are toggles. Additionally, typewriter and underlined style are available from the Edit/Text Style menu.
      strikethrough (CTRL+t) is a useful style for TODO lists to indicate items that have been processed but you don't want to delete yet.
      Try coloring cells with the two color selectors in the toolbar. You can double-click on the current colors to set them instantly. Select cell(s) that contain grid(s) and use the border color drop down, or Edit/Set Border Width menu to change their look.
      Add a note to a cell for anything that shouldn't clutter its text, such as details, sources or reminders: select the cell and press CTRL+E (Edit > Edit Note). A cell with a note shows a small triangle in its top-right corner. Point at the triangle to read the note, and click it to edit the note. This cell has a note, try it! With View > Filter > Show cells with notes you find all of them.

    Tags & Hierarchy
      Tags are a good way to deal with words that you use repeatedly in a sheet, like statuses, categories etc. To make something a tag, find an occurrence, and do "Add Cell as Tag" (Edit/Tag... menu). From now on, you can set any other cell to a tag with CTRL+Right Mouse Button (popup menu). Tags are colored blue, to signal to you it is a tag. This helps spotting if a tag is mistyped.
      A powerful operation that works well with tags is "Hierarchy Swap". An Example of what it does:
        The motivation behind Hierarchy Swap is that you use TreeSheets to organize your data in tree format, but often, trees are not ideal to organize data, because they force you to make choices about what subdivision is most important. 
        Say that I am organizing a project, and I am trying to keep track of what tasks it involves. I am using tags to indicate the people that work on it, the deliverables, and the topic areas:
          milestone 1
            front end
              fred
                fix the GUI
                connect to database
              bob
                overhaul graphics
            back end
              fred
                add input forms
          milestone 2
            back end
              fred
                set up new tables
              bob
                buy new servers
                set up networking
        Notice how in the above table, milestones are the most important subdivision, the topic areas second, and people the least important. This a pretty arbitrary choice, we might want to see things from a people perspective, and now with Hierarchy Swap you can! Select any occurrence of "fred", and press F8 twice, and you'll get this:
          fred
            milestone 1
              front end
                fix the GUI
                connect to database
            back end
              milestone 1
                add input forms
              milestone 2
                set up new tables
          bob
            milestone 1
              front end
                overhaul graphics
            milestone 2
              back end
                buy new servers
                set up networking
        Effectively what you've done is saying: "show me this hierarchy from fred's perspective". You can now see exactly what he works on. You could do the same for bob, if needed. If you want to see what fred is doing on the back end, press F8 just once on "back end" (within fred), and you have tweaked your perspective yet again. Press once more, and now front/back end becomes the major subdivision.
        Keep pressing F8 on various tags, to see how you can attain any perspective you need.
        Important to note is how on any swap, the tag that was previously the parent, now becomes the child of the selected tag. This means that it doesn't matter how often you do this swap, no information is lost. It means that you should be able to get the tree back in its original configuration if you wanted to.
        So you can see this feature as allowing you to have snippets of information which can have any number of tags associated with them. The Hierarchy Swap allows you to determine the current order of importancy of tags, and thus, the tree view is nothing but the most recent view
        You can still keep editing data to this tree whatever "view" it is in, no need to reset the tree to its original order. Trees like this have no set order!
        Note how promoting "fred" doesn't automatically promote "bob". TreeSheets doesn't know that these tags are of the same "type". Not all uses of tags have clear cut types, and its not always necessary to reorder all at once, so this keeps the feature simple.

      TreeSheets is great for presentations. Unlike traditional tools like powerpoint, which make it really difficult to convey a sense of structure to the audience, you can organize a treesheet as if your entire presentation was a single "slide", and have minimized sub-slides that you can zoom into. To help its use as a presentation tool, TreeSheets has two viewing options: Fullscreen View (F11) to reduce visual clutter, and Scaled View (F12) which tries to make the current view as large as possible.
        Note, both this feature and printing make use of a scaling method that does not preserve rendering fidelity in all cases. This will be fixed in a future version.

        You can use SUM, MIN, MAX, AVG, MEDIAN and COUNT, together with numbers, + - * / and parentheses, e.g. =(SUM(Income) - SUM(Costs)) / 12. Only the numbers directly in the named grid count, and the results of other formulas count as numbers too.       Templates start new documents from one you have set up before, such as a weekly plan or a project outline. You find them in File > New from Template:
        Add Current Document as Template adds the file of the current document to that menu (save it first), and Add Files as Templates... adds other TreeSheets files.
        Clicking a template there creates a new, unnamed document with a copy of its content. The template file itself stays as it is, since saving asks for a new file name.
        Open File as Template... does the same with any TreeSheets file without adding it to the menu, and Remove Template... takes a template off the menu again (the file stays where it is).
      If you work on TreeSheets files on multiple computers, store them in a shared folder (such as DropBox) and turn on Options -> Auto reload documents
        This way, you will always be up to date on all your machines when you save the document
      Running TreeSheets from the command line
        You can run TreeSheets from the command line
        as arguments, you may specify a single file to load
          If TreeSheets is already running in the system, this will cause it to pass the file to the existing instance, then quit
        you may also run it with -p as an argument
          This starts TreeSheets in "portable" mode, where (on Windows) it writes settings to a .ini file in the current directory rather than to the registry
        Note that to run correctly from the command line, at least on Windows, TreeSheets.exe needs to be started with a full path, otherwise it will not be able to find its icons etc. relative to the executable path.
