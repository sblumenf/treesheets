# Milestone 7: import and export

Status: finished, with the limits listed under "Left out, or doubtful". This is the last
milestone of the proof of concept. All checks pass (`cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`): the
counts and the time are under "Tests". `cargo check --target wasm32-unknown-unknown -p
wombat-core -p wombat-search` passes. Decisions A95-A104 and B80-B86 are new. The file format
of documents did not change. No dependency was added.

**An independent review found thirteen things wrong or missing, and they were fixed**
(decisions A113-A120 and B95-B99). The text below describes the state after the fixes; what
was found, what changed and how it was checked is in "Fixes after review" at the end.

A Wombat document is a tree of grids: any cell can hold another grid. A spreadsheet is one
flat grid per sheet. So every export has to decide what happens to the grids inside cells, and
this milestone built three answers: leave them out, repeat the outer rows beside the inner
ones, or write one table per grid with keys that join them.

## What was built

- **`wombat_core::convert`** (about 1,560 lines, no file access, builds for the web):
  - `delimited.rs`: writing and reading comma, semicolon and tab separated text, finding the
    delimiter of a file that does not say it, and the rule that keeps exported text from
    running as a formula in a spreadsheet.
  - `export.rs`: one grid as a table (`grid_csv`), a grid flattened with everything nested in
    it (`flat_csv`), TreeSheets' indented text (`outline`).
  - `lookup.rs`: the lookup-style export, one table per grid.
  - `names.rs`: file names made from cell text.
  - `import.rs`: decoding a file (the encoding is never guessed), reading delimited and
    indented text into a `Table`, and making a document of it.
- **`Command::Import`** (`edit/import.rs`): a `Table` becomes the grid of a cell, as one
  undoable command; a grid with content is replaced only when asked.
- **`wombat_core::export_files`**: writing an export to a file or a folder, safely.
- **The tool**: `wombat export`, `wombat import` for `.csv`, `.tsv` and `.txt` beside `.cts`,
  and `import CELL FILE` in `wombat edit`.
- **The referee** (`referee/exports/`): what the real TreeSheets exports and imports, with the
  script that regenerates it; and `check_lookup_libreoffice`, which opens a lookup export in
  a real LibreOffice and enters the README's formulas (optional, not run by the tests).

## Each format, with an example

The document of the examples: three projects, the first two with tasks in their first cell.

```
Apollo   | Ana   | 2026          inside "Apollo":    Design the logo | Ben | done
Borealis | Chidi | 2027                              Write the brief | Ana | open
Cygnus   | Eve   | 2028          inside "Borealis":  Survey          | Dee | open
```

### One grid (`--format csv`, `--format tsv`)

One line per row of the grid of the chosen cell (by default the root). A cell that has a grid
of its own is exported as its text alone; what is nested is left out. Every row and column is
exported, the empty ones too. This is TreeSheets' "CSV (flat)" and "TSV (flat)".

```
Apollo,Ana,2026
Borealis,Chidi,2027
Cygnus,Eve,2028
```

### Flattened (`--format flat`)

One line per innermost row, after the rows it is inside of. The document is not changed.

```
Apollo,Ana,2026,Design the logo,Ben,done
Apollo,Ana,2026,Write the brief,Ana,open
Borealis,Chidi,2027,Survey,Dee,open
Cygnus,Eve,2028,,,
```

The exact rule (decision A99), which makes the result a rectangle whatever the nesting:

- Every level of nesting has its own block of columns, as wide as the widest grid at that
  level. Rows of narrower grids are padded with empty fields on the right.
- A row that is not nested as deep as others has empty fields in the deeper blocks (Cygnus).
- A row with a nested grid has no line of its own: its cells, the text of the cell that has
  the grid included, are repeated on every line that comes from that grid.
- A row with several nested grids gives the lines of each grid in turn, after the same outer
  row.
- Empty cells are empty fields. Rows that are entirely empty are kept.
- **Parent columns** (decision A118). A row with grids in two of its cells gives lines that do
  not say which cell they came from: `P` with `p1`, `p2` inside and `Q` with `q1` inside, in
  one row, gave `P,Q,p1` / `P,Q,p2` / `P,Q,q1`. So when any row of the export has more than
  one nested grid, every line ends with one more column per level below the first. It holds
  the letter that the column of the parent cell has in this very table, as the spreadsheet
  shows it; it is empty where the line is not nested that deep.

  ```
  P,Q,p1,A        <- p1 is inside the cell in column A of this line: P
  P,Q,p2,A
  P,Q,q1,B        <- q1 is inside the cell in column B: Q
  solo,,,         <- not nested: no parent
  ```

  `--parent-columns` adds these columns to any flattened export, `--no-parent-columns`
  leaves them out always. Letters at the end were chosen over a text in front because a
  letter can be checked by eye against the same line, can be filtered on, is still exact
  when two cells have the same or no text, and shifts no other column. With `--notes` the
  letters count the note columns too.

An irregular example: level 1 is two columns wide; `A` has a grid of three columns, `B` one of
one column, in which `deep` has a grid again; the last row is empty.

```
A,B,a1,a2,a3,,A,       <- the row of A's grid; it is inside column A
A,B,deep,,,d1,B,C      <- B's grid is narrower: padded; d1 is at level 3, inside `deep` (C)
A,B,deep,,,d2,B,C
A,B,b2,,,,B,           <- b2 has nothing inside: level 3 is empty
solo,,,,,,,            <- nothing nested at all
,,,,,,,                <- an empty row
```

(The first row has grids in both `A` and `B`, so the two parent columns are there unasked.)

**When this equals TreeSheets' Flatten.** This goes by rows; TreeSheets' Flatten (milestone
3b, `Command::Flatten`) goes by cells and changes the document. The flattened export is
exactly the table that Flatten makes when **every grid in the exported cell has one column**
(an outline) and the export is of what the cells show (the default, not `--formulas`) with
`--raw`, so that no text is guarded. Then no row can have two nested grids, so no parent
column appears unasked. A test compares the two on random outlines. As soon as a grid has
two columns they differ: Flatten makes a row per innermost cell, the export a line per
innermost row.

### Lookup-style (`--format lookup`): tables that join

The output is a folder: one CSV file per grid, `index.csv` and `README.txt`.

```
out/table-ac80c252.csv       the top grid
out/Apollo-0e73142d.csv      the grid inside "Apollo"
out/Borealis-a33b6a3b.csv    the grid inside "Borealis"
out/README.txt
out/index.csv                written last: a folder without it is an unfinished export
```

`table-ac80c252.csv` (IDs shortened here to their first 8 digits; the files have all 36
characters):

```
A,B,C,row_id,A_id,B_id,C_id,A_table
Apollo,Ana,2026,0e73142d,0e73142d,09bb070f,a058044c,Apollo-0e73142d.csv
Borealis,Chidi,2027,a33b6a3b,a33b6a3b,78bae1e5,5c4aefbe,Borealis-a33b6a3b.csv
Cygnus,Eve,2028,6ef17f87,6ef17f87,ecb78473,7566a58e,
```

`Apollo-0e73142d.csv`:

```
A,B,C,row_id,A_id,B_id,C_id,parent_table,parent_row_id,parent_cell_id
Design the logo,Ben,done,e3717457,e3717457,dd66e52b,d04844cd,table-ac80c252.csv,0e73142d,0e73142d
Write the brief,Ana,open,cd890afa,cd890afa,5e75553c,ca146ff4,table-ac80c252.csv,0e73142d,0e73142d
```

The columns, in this order (decision A100):

| Columns | What |
| ---- | ---- |
| `A`, `B`, `C`, ... | The cells of the grid: the names the columns have in the spreadsheet they land in. With `--notes`, `A_note` after `A`, and so on |
| `row_id` | The key of the row: the permanent ID of the row's first cell |
| `A_id`, `B_id`, ... | The permanent ID of every cell |
| `A_table`, ... | Only for columns that have nested grids: the file of the table inside the cell, or empty |
| `parent_table` | In every table but the top one: the file of the table this one is nested in |
| `parent_row_id` | The `row_id`, in that table, of the row it is nested in |
| `parent_cell_id` | The ID of the cell it is nested in (one of the `_id` columns of that row) |

- **Why `row_id` is the first cell's ID, and how long it stays.** Cells have permanent IDs
  and rows have none, and a nested grid sits in one particular cell. The first cell stands
  for its row. So `row_id` is the ID of the row's first cell: **stable as long as that cell
  exists and stays first in its row.** Sorting rows keeps it (rows move with their cells).
  Deleting that cell, swapping or moving columns, or transposing the grid changes which cell
  is first, and with it the `row_id` of the row. The `_id` of a cell never changes. (Here
  the grids sit in the first column, so `parent_row_id` and `parent_cell_id` are equal; in
  general they differ.)
- **The readable columns are first**, the ID columns last: XLOOKUP does not need its key in
  the first column.
- **Column names are letters**, and every row is data, because a grid has no header row in
  Wombat and guessing one would silently drop a row from some tables. `--header-row` takes
  the names from each grid's first row instead and leaves that row out, except for a grid of
  one row or with a nested grid in its first row; `index.csv` says which it was per table.
- **`index.csv`** has one row per table: `table`, `trail` (the texts on the way to the cell it
  sits in), `rows`, `columns`, `header_row`, `parent_table`, `parent_row_id`,
  `parent_column`, `cell_id`, `cell_text`.
- **File names** are `<words>-<8 digits of the cell's ID>.csv` (decisions A101 and A117): the
  words come from the trail with everything that is not a letter or digit turned into `-`,
  the whole at most 31 UTF-16 units, which is how Excel counts the 31 characters of a sheet
  name (a letter outside the Basic Multilingual Plane is two), so that a file opens as a
  sheet of the same name. So a name has none of `[ ] : * ? / \` and no apostrophe. They are
  safe on Windows, macOS and Linux whatever the cells say, differ in a lower-case ASCII
  suffix (so also where a file system ignores case), and stay the same between exports.
  Two tables of one export whose IDs start with the same eight digits (among 10,000 tables
  with random IDs: about one export in a hundred) get sixteen digits, those two only; the
  other names do not change.
- **Nothing is lost.** A test rebuilds the whole tree of texts and cell IDs from the folder
  alone and compares it with the document.

**The worked example**, as `README.txt` gives it for these files: to show, beside every task,
the project it belongs to, get `Apollo-0e73142d.csv` and `table-ac80c252.csv` into one
workbook as sheets named after the files. In sheet `Apollo-0e73142d`, `parent_row_id` is
column I and the first free column is K. In K2, and filled down (D is the `row_id` column of
the top table):

| Program | Formula |
| ---- | ---- |
| Excel 2021 or 365, Google Sheets | `=XLOOKUP(I2, 'table-ac80c252'!D:D, 'table-ac80c252'!A:A)` |
| LibreOffice 24.8 or later | `=XLOOKUP(I2, $'table-ac80c252'.D:D, $'table-ac80c252'.A:A)` |
| Every version of Excel and Google Sheets | `=INDEX('table-ac80c252'!A:A, MATCH(I2, 'table-ac80c252'!D:D, 0))` |
| Every version of LibreOffice | `=INDEX($'table-ac80c252'.A:A, MATCH(I2, $'table-ac80c252'.D:D, 0))` |

Each gives `Apollo` for both tasks. The other way round, the number of tasks of each
project, in a free column of `table-ac80c252`: `=COUNTIF('Apollo-0e73142d'!I:I, D2)`, in
LibreOffice `=COUNTIF($'Apollo-0e73142d'.I:I, D2)`.

- **The sheet reference differs.** LibreOffice writes `$'name'.D:D`; the Excel form
  `'name'!D:D` gives `Err:504` there. The README gives both, labelled.
- **Argument separators.** Where the comma is the decimal sign, formulas take `;` between
  arguments in all three programs; the README says so.
- **How a sheet gets its name.** LibreOffice names the sheet of an opened CSV file after
  the file without `.csv` (verified); Excel is documented to do the same; in Google Sheets
  File > Import > "Insert new sheet(s)" names the sheet after the file, and the README says
  to rename it if it did not.
- **Excel and the list separator.** Excel in a system whose list separator is `;` is
  reported to open a comma separated file with every row in one column (not verified here).
  For such a system export with `--delimiter semicolon`; the README says so.
- **Verified in LibreOffice 25.8.7** with `referee/exports/check_lookup_libreoffice`:
  see "Fixes after review". **Excel and Google Sheets could not be run here: what is said
  about them is from their documentation and is unverified.**

### Indented text (`--format text`)

TreeSheets' "Indented text": one line per cell, the cells of a grid row by row, two more
spaces per level; a cell with an image has a space after its text. Formula cells are written
as what they show. A line break inside a text is written as a space (A174).

```
                     <- the root cell's own line (it has no text)
  Apollo
    Design the logo
    Ben
    done
    ...
  Ana
  2026
  Borealis
```

Lines end in CR LF, which is what TreeSheets writes on Linux and Windows, or with `--lf` in
LF, as it does on macOS.

## What a cell exports as, and the safety rule

- **A formula cell exports what it shows.** `--formulas` exports the formula instead.
- **Only text is exported**, and with `--notes` the note, in a column after each column.
  Styles, colours, images and links are not.
- **Formula injection** (decision A114). A spreadsheet that opens a CSV file may take a
  field for a formula. A formula can read other cells, fetch from a web address, or on
  older systems start a program; this is a known attack on exported files ("CSV
  injection"), and a document can hold text from anywhere. So by default a text that a
  spreadsheet could run gets a single quote in front (`=1+1` is written `'=1+1`), in all
  three table exports, in notes, in column names taken from cells and in `index.csv`.
  **The quote is visible in the spreadsheet.** LibreOffice (verified) and Excel
  (documented) show it as a character of the cell when they open a CSV file; only typed
  into a cell does a leading quote disappear. It is the price of a file that cannot run
  anything, so the rule guards as little ordinary text as it safely can. It goes by the
  first character:

  | Starts with | Guarded | Left as it is |
  | ---- | ---- | ---- |
  | a tab or carriage return | always | |
  | `=` | always: `=1+1`, `==`, `= in prose`, `=cmd\|' /C calc'!A0` | the text `=` alone |
  | `+` or `-` | what goes on like a calculation, a name or a call: `+1+1`, `-1+1`, `-a`, `-item`, `-A1`, `+SUM(1)`, `-cmd\|' /C calc'!A0`, `-.`, `+1e` | only signs, dashes and spaces: `-`, `--`, `+`, `- -` |
  | | | a sign, then digits, spaces and `( ) . , / -` with at least one digit: `-5`, `+2.5`, `-1,5`, `+44 20 7946 0958`, `+1 (555) 010-0100`, `+1-555-0100`, `-2026-03-04`, `+1/2`; and `-2e10` |
  | | a list item with a parenthesis, a `\|`, or a `!` before a letter, digit, `$`, `'`, `_` or `#`: `- SUM(1)`, `- call mum (tomorrow)`, `- cmd\|' /C calc'!A0`, `- 'S'!A1` | a sign, a space and any other text: `- item one`, `+ a plus point`, `- Done! Next` |
  | `@` | with a parenthesis, a `\|` or such a `!`: `@SUM(1)`, `@a (b)`, `@x\|y` | `@handle`, `@`, `@ home` |
  | full-width `＝`, `＋`, `－`, `＠` | as `=`, always, always, as `@` | `＝` alone, `＠name` |
  | `'` before any of the guarded | one more quote: `'=1+1` is written `''=1+1` | `'quoted`, `'-5` |
  | anything else | never | ` =1+1` (a space first), `a=b`, `1+1` |

  The reason for the three marks: a formula needs a parenthesis to call a function, a `|`
  for a DDE link, and a `!` to refer to another sheet or workbook; without them it can only
  calculate or fail. Where the rule is not sure it guards, which is why
  `- call mum (tomorrow)` gets a quote.
- **What is left alone can still be shown differently.** A spreadsheet may calculate
  `+1-555-0100` or show `#NAME?` for `- item one`: Excel is documented to treat a field that
  starts with `+` or `-` as a formula. That cannot do anything, it is the same kind of
  change as `00123` becoming 123 (below), and the remedy is the same: import the column as
  text. LibreOffice 25.8 does neither: it takes only a field that starts with `=` for a
  formula (verified with `-item`, `-A1`, `+1+1`, `@SUM(1)`, `- SUM(1)`: all text).
- **`--raw`** switches the protection off, for files that go to a program and not to a
  spreadsheet. The indented text export has no such protection: it is not a spreadsheet
  format.
- **Taking the guard off again: `--unguard` on import.** A file exported with the guard and
  imported again has the quotes in its texts. `wombat import --unguard` (`Table::unguarded`)
  takes away exactly the quotes that the export added; because a text that already started
  with a quote before something guarded got one more, the texts come back as they were,
  whatever they were (a test over random texts). It is off by default and only for files
  that Wombat exported: in a file from anywhere else `'=1+1` cannot be told from a text
  that its author wrote with the quote, so nothing is stripped unasked.
- **What a spreadsheet does to values when it opens a CSV file.** CSV is text, and the
  spreadsheet decides what each value is. Verified in LibreOffice 25.8 with the settings its
  import dialog proposes:

  | Exported text | LibreOffice shows |
  | ---- | ---- |
  | `00123` | the number 123 |
  | `12345678901234567890` | the number 1.23456789012346E+019 |
  | `2026-03-04` | a date |
  | `-2026-03-04` | the number -1433530 (a negative date) |
  | `-5` | the number -5 |
  | `1e5` | the number 100000, with "Detect numbers in scientific notation" on (its default); text with it off |
  | `TRUE`, `1/2`, `-5%` | text; with "Detect special numbers" on: 1, a date, -0.05 |
  | the IDs, `+44 20 7946 0958`, `+1-555-0100`, `- item one`, `@handle`, `-1,5`, `'=1+1` | text, unchanged |

  Excel is documented to do the same to `00123`, long numbers and dates, and also to `1/2`
  and `1e5` (not verified here). No export option changes this: writing `="00123"` would
  make every such cell a formula. **Where the exact text matters, import the columns as
  text:** in LibreOffice select the columns in the import dialog and choose the column type
  Text; in Excel use Data > From Text/CSV > Transform Data, or the Text Import Wizard with
  the column format Text; in Google Sheets import with "Convert text to numbers, dates and
  formulas" off. `README.txt` of a lookup export says this too.

## Options and defaults

| Option | Default | Why |
| ---- | ---- | ---- |
| Delimiter (`--delimiter comma\|semicolon\|tab`) | comma (`tsv`: tab) | What "CSV" means |
| Byte-order mark (`--no-bom`) | written | Without it Excel shows every non-ASCII letter wrong, silently; with it a few programs show three junk bytes, visibly |
| Line end (`--lf`) | CR LF | RFC 4180 |
| Quoting (`--quote-all`) | only where needed | Readable; a field with a comma, a semicolon, a tab (whichever is the delimiter: a spreadsheet's import dialog proposes all three at once, A113), a quote or a line break is quoted, and a row of one empty cell is written `""` |
| Injection protection (`--raw`) | on | Above |
| Parent columns of a flattened export (`--parent-columns`, `--no-parent-columns`) | when a row has more than one nested grid | Only then do the cells not say where a line came from |
| Formula cells (`--formulas`) | as what they show | What a reader of a table wants |
| Notes (`--notes`) | not exported | Most documents have none |
| Column names of lookup tables (`--header-row`) | letters | A grid has no header row |
| Existing output (`--overwrite`) | refused | Below |
| `--treesheets` | off | The bytes TreeSheets writes: no mark, LF, every field of CSV quoted (of TSV: only one with a tab, a quote or a line break), nothing protected |
| On import: text that starts with `=` (`--formulas`) | plain text | A file from elsewhere should not start calculating; it is also what TreeSheets does |
| On import: encoding (`--encoding utf-8\|utf-16le\|utf-16be\|windows-1252`) | UTF-8, or UTF-16 if the file starts with its byte-order mark; anything else is refused | Nothing is guessed (A115) |
| On import: delimiter of a `.csv` file (`--delimiter`) | looked for in the file, else comma | A semicolon or tab file named `.csv` is common (A120) |
| On import: the export's guard (`--unguard`) | kept | Only Wombat's own exports can be told (A114) |
| On import into a cell: a grid with content (`replace`) | refused | Nothing is replaced unasked (A119) |

An export also prints how many cells it wrote as error values (`#LIMIT!`, `#NAME?` and the
like), if any, and an import prints the encoding and the delimiter it used and why.

## Import

- **Delimited text** (`.csv`, `.tsv`, and `--format semicolon`) becomes one grid: a row per
  line, short rows padded with empty cells to a rectangle. **The delimiter of a `.csv` file
  is looked for in the file** (`delimited::detect`, decision A120), because that name is
  used for semicolon and tab separated files too: the first 100 lines are read as the
  importer reads them, so that a delimiter inside a quoted field does not count, and a
  candidate is a delimiter that occurs in every line the same number of times. One
  candidate: that one. A tab among several: the tab. Comma and semicolon both: the semicolon
  if every comma stands between two digits (`1,5;2,5`), else no answer. Fewer than two
  lines, or no candidate (one column of sentences with commas in them): no answer, and the
  file is read by commas, as its name says. `--delimiter` overrides all of it, and the tool
  prints what it used: `read as UTF-8, fields separated by semicolons (found in the file)`. It is read as RFC 4180 says: a
  quoted field may hold the delimiter, doubled quotes and line breaks. **A line break inside
  a quoted field is kept** as a line break of the cell's text (since A174; until then it
  became a space, as in TreeSheets); tabs and other control characters become spaces. Empty lines are skipped. What is not valid CSV is
  read without complaint: a quote in the middle of a field is a character, a quote that is
  not closed runs to the end of the file.
- **Indented text** (`.txt`) is read as TreeSheets reads it: every line is a cell of a grid
  of one column; a line indented further than the level it is in goes into the grid of the
  line before it. Each leading space or tab is one step; any deeper indentation is one level,
  however many steps; the first line sets the top level; empty lines are skipped, and a line
  of only spaces is an empty cell.
- **Encodings: nothing is guessed** (decision A115). A file is UTF-8, with or without a
  byte-order mark, or UTF-16 if it starts with the byte-order mark of UTF-16 (Excel's
  "Unicode text"). Anything else is refused with the place of the first byte that does not
  belong: `the file is not UTF-8: byte 16 (counted from 0) does not belong; if it is in
  another encoding, say which`. `--encoding windows-1252` (Excel's plain "CSV" on Windows),
  `utf-16le` or `utf-16be` (UTF-16 without a mark) read it as that. The byte-order mark is
  never part of the text. The import says what it read the file as.
- **Formulas:** text that starts with `=` is plain text unless `--formulas` is given; then it
  is a formula cell, as if typed.
- **Where it goes:** `wombat import FILE NEW.wombat` makes a new document whose root has the
  grid. `import CELL FILE` in `wombat edit` gives the grid to an existing cell; the cell
  keeps its text. That is one command (`Command::Import`): new cells with new IDs that look
  like the cells of a new grid there, one unit of undo, a change report like any other, and
  refused if the document would have too many cells, nest too deep or be too large to save.
- **Over what is there: only with `replace`** (decision A119). A cell without a grid, or
  with a grid of empty cells, takes an import. A grid in which any cell has text, a note, an
  image or a grid is replaced only if the command says `replace` (`import /1,1 extra.csv
  replace`), and refused without; the root cell is no exception. The tool then prints how
  many cells went and how many links of the document pointed at them (`removed 6 cells that
  were there; 1 link of this document pointed at them and now points at nothing`). An
  interface asks `LinkIndex::would_break` with the cells of the grid before the command,
  which also knows the links from other documents of a workspace; the tool sees one
  document.
- **Bounds on hostile files:** at most 32 MiB; rows times columns after padding under the
  limit on cells (700,000), counted before the rectangle is made; a field at most 16 million
  characters; nesting at most 32 levels (deeper lines become rows of the last level). Reading
  takes time in proportion to the size of the file.
- **What a document can hold is said before one is made** (decision A119). A saved document
  is at most 32 MiB, and a cell takes at least 49 bytes of it, its text 12 more than its
  length. A table that cannot fit is refused when it has been read, with the numbers:
  `600000 cells with their text would make a document of at least 37200000 bytes; a document
  may be at most 33554432 bytes, which is room for at most about 541200 cells such as these
  (and never more than 700000); import a part of it`. That takes a quarter of a second for
  600,000 rows of one letter; before, the document was built first and refused at saving
  after 2.3 seconds with "the file would be larger than 33554432 bytes". The limit of
  700,000 cells cannot be reached by an import: 684,784 empty cells fill a file.

## Writing files safely

Two earlier reviews found writes that followed a planted symbolic link and overwrote another
file. Exports write under names that come partly from the document, so (decision A103):

- An existing file, or a folder with anything in it, is not written to without `--overwrite`.
- **`--overwrite` replaces a regular file and nothing else** (decision A116). A device, a
  FIFO, a socket, a folder or a symbolic link at the place of a file is refused, with or
  without `--overwrite`, for a single file and for every file of a lookup folder. It is not
  opened, not followed and not removed.
- A symbolic link at the output file, at the output folder or at any file in the folder is
  refused, **however the path is written**: `link/` and `link/.` are the link, not the
  folder it leads to (the path is reduced to its components before it is looked at).
- A file is written to a new temporary file beside it, created so that an existing name
  fails, and renamed into place; renaming replaces a name and follows nothing.
- Every file name of a folder export is checked to be one plain name (no separator, not `.`
  or `..`), whatever made it, and everything is checked before the first file is written or
  removed.
- Cell text reaches a path only through the name rule above.
- **A lookup folder is written into again only if it is one** (decision A117). With
  `--overwrite`, a folder that has anything in it must have an `index.csv` of a lookup
  export, else it is refused. The tables that this index lists and the new export does not
  write are removed first, so that no table of a grid that is gone stays beside the new
  index and still joins. Only those: a name from the old index is removed if it is a plain
  name ending in `.csv` of a regular file in that folder. Every other file stays.
- The tables are written first, then `README.txt`, then `index.csv`. **A folder is not
  replaced as a whole:** a folder that is not empty cannot be renamed over, and removing
  the old one whole would remove files the export did not write. If writing stops half way,
  the folder has the old index or none. With the old index, exporting again with
  `--overwrite` puts it right; without one, the folder is refused and has to be removed by
  hand.

Each has a test: a link planted at the file, at the temporary name, at the folder, at the
name of a table (the last one, to see that nothing else is written or removed first); a
FIFO and a socket at the file and at the name of a table; `link/`, `link//` and `link/.`;
an old index that lists `../beside.csv`, an absolute path, a folder, a link and a `.txt`
file; folders with no index, an empty one, one of somebody else's; `..`, absolute paths,
`CON`, `nul.csv`, `index`, `-rf` and the like as cell texts; a property test of the names.
Devices are stood in for by FIFOs and sockets made in the test's own folder: no test
touches a path outside it.

**Every place where the tool writes at a path the user gave** (audited for decision A116):

| Command | Path | What is written, and the rule |
| ---- | ---- | ---- |
| `export` (csv, tsv, flat, text) | the output file | `export_files::write_file`: nothing or a regular file, the latter only with `--overwrite` |
| `export --format lookup` | the output folder | `export_files::write_folder`: as above per file; not a link; an existing folder only if empty or a lookup export |
| `new`, `copy`, `import` (text and `.cts`) | the new document | `new_path`: refused if anything is there (a link to nothing included, since this review) or if the name ends in a separator; then `storage::save_document` |
| `import` of a `.cts` file | `<name>.images/` and the view-state folder beside the new document | the storage layer's own names: `write_own` replaces a link, never writes through one (A87) |
| `edit` (`save`), `copy-cell`, `move-cell`, `replace` | documents that were just loaded from that path, and for `edit` the view-state file beside it | `storage::save_document`, `save_two`: a link there is the user's own and is followed (A27); only a file that loaded as a document is written. The view state has the storage layer's own name |
| `import-all` | the new folder | `create_dir_all`, then one new document per file through the storage layer; milestone 6's code, in review separately |
| `links --cache`, `search`, `backlinks --cache` | the cache folder | `scan.rs`; milestone 6's code, in review separately |

## Compared with the real TreeSheets

`referee/exports/make_exports` drives the app headlessly. CSV and indented text come from
the script function `ts.get_subtree_text`. TSV export and all imports have no script function:
the menu action is triggered by a key press on the private display and the file dialog that
opens is answered by key presses too (`referee/exports/README.md`). Running it twice gave the
same files. The tests need no app.

| What | Compared | Result |
| ---- | ---- | ---- |
| Indented text of every example and the fixture (`referee/golden/*.txt`) | 38 documents, over 500,000 bytes | 38 identical, byte for byte. No special case. The one normalisation is the referee's own: it stored LF where the app wrote CR LF; with CR LF the export equals the golden text with its line ends put back |
| CSV of the root's grid of the same documents | 38 | 38 identical with `--treesheets` |
| The ten cases of `referee/exports/fixture.cts` as CSV | 10 | 10 identical |
| The same as indented text, with the app's CR LF | 10 | 10 identical |
| The same as TSV | 10 | 7 identical, 3 differ on purpose (below) |
| Menu export of the whole fixture as text and as CSV, and menu against script function | 3 | identical |
| Import of 15 CSV, 1 semicolon, 2 TSV and 7 indented text files | 25 | 23 identical trees, 2 differ on purpose (below) |

Every mismatch and its cause:

- **TSV, case `quotes`:** TreeSheets quotes a TSV field only if it starts with a quote or
  holds a tab, so it writes `say "hi"` and `a"b` bare. A quote in a field that is not quoted
  is not valid delimited text. Wombat writes `"say ""hi"""` and `"a""b"`.
- **TSV, cases `blank` and `tree`:** TreeSheets writes a row that is one empty cell as an
  empty line. No reader takes an empty line for a row, TreeSheets' own importer included, so
  the row is lost on the way back. Wombat writes `""`. (The test reimplements TreeSheets'
  rule and gets all ten of the app's files from it, to show that these are the only causes.)
- **Import, `trailing_delimiter.csv` (`a,b,`):** TreeSheets drops an empty field at the end
  of a line; Wombat keeps it, as RFC 4180 says. Otherwise a table whose last column is empty
  comes back one column short.
- **Import, `after_quote.csv` (`"abc"x,def`):** TreeSheets drops one character after a
  closing quote, whatever it is, and reads `abc`, an empty field, `def`. Wombat keeps the
  text with the field: `abcx`, `def`. The file is not valid CSV; there is no right answer,
  but losing a character silently is the worse one.

One difference was found and removed: a quote that is not closed and a file that ends with a
line end. Wombat made the final line end a space at the end of the text; TreeSheets does not,
and now neither does Wombat.

TreeSheets' CSV export is valid RFC 4180 apart from the line end (LF on Linux): it quotes
every field and doubles quotes, and its cell text has no line breaks. Its TSV export is not, as
above. Also confirmed with the app: it imports `=1+2` as plain text, drops a byte-order mark,
and turns a tab inside a quoted field into a space.

## How to try it (the demo)

From `wombat/`, after `cargo build`, with `target/debug` on the path:

```sh
cat > projects.txt <<'EOF'
Apollo | Ana | 2026
  Design the logo | Ben | done
  Write the brief | Ana | open
Borealis | Chidi | 2027
  Survey | Dee | open
Cygnus | Eve | 2028
EOF
wombat new projects.wombat --from projects.txt

wombat export projects.wombat --format lookup out     # the folder of tables
ls out
cat out/README.txt                                    # the layout and the XLOOKUP formula
cat out/index.csv out/table-*.csv out/Apollo-*.csv

wombat export projects.wombat --format flat --no-bom -          # flattened, to the screen
wombat export projects.wombat --format csv projects.csv         # the top grid alone
wombat export projects.wombat --format text --lf -              # indented text
wombat export projects.wombat --format csv --treesheets --cell /1,1 -   # one cell's grid

printf 'Launch,Eve,open\nReview,Ana,"=1+1"\n' > extra.csv
wombat import extra.csv extra.wombat                  # a new document from a CSV file
printf 'import /1,3 extra.csv\nchanges\nundo\nredo\nsave\n' | wombat edit projects.wombat --script -
wombat export projects.wombat --format flat --no-bom -          # Cygnus now has two tasks

printf 'a;b;c\n1,5;2,5;3\n' > semi.csv
wombat import semi.csv semi.wombat                    # semicolons, found in the file
printf 'caf\xc3\xa9,bad\xff\n' > bad.csv
wombat import bad.csv bad.wombat                      # refused: byte 9 is not UTF-8
printf 'import /1,1 extra.csv\n' | wombat edit projects.wombat --script -          # refused
printf 'import /1,1 extra.csv replace\nsave\n' | wombat edit projects.wombat --script -
wombat export projects.wombat --format lookup --overwrite out   # again, into the same folder
```

The first export prints the five files; `README.txt` has the formulas
`=XLOOKUP(I2, 'table-…'!D:D, 'table-…'!A:A)` and, for LibreOffice,
`=XLOOKUP(I2, $'table-…'.D:D, $'table-…'.A:A)` with the real names, and the same with
`INDEX` and `MATCH`. The export after the first import prints the two new lines
`Cygnus,Eve,2028,Launch,Eve,open` and `Cygnus,Eve,2028,Review,Ana,'=1+1`: the imported `=1+1`
is plain text, and exported again it is guarded. `semi.csv` imports as 3 columns by 2 rows
with the line `read as UTF-8, fields separated by semicolons (found in the file)`. The
import over Apollo's tasks is refused without `replace`, and with it prints `removed 6
cells that were there`. The last export writes the tables again; had a grid gone in between,
its table would have been removed from the folder. `wombat export --help` and `wombat import --help` list the options.

## Left out, or doubtful

- **Excel and Google Sheets were not run.** LibreOffice 25.8 was, after the review
  (`check_lookup_libreoffice`, below): the tables open as written, the sheets get the
  files' names, and the README's LibreOffice formulas give the right values. What is said
  about Excel and Google Sheets (the form of their formulas, how sheets get their names,
  what Excel does where the list separator is `;`, what it makes of `+1-555-0100` or
  `- item`) is from their documentation and **unverified**. This is the first thing to try
  by hand.
- **What a spreadsheet does to values when it opens a CSV** (`00123` becomes 123, long
  numbers are rounded, dates are recognised) is documented above and in the README, with
  the advice to import columns as text; no export option avoids it. The future workbook
  export would.
- **The guard's quote is visible** in the spreadsheet cell. `--unguard` takes it off again
  on import, for Wombat's own exports only. A tab in front, the other common choice, is
  invisible but breaks more readers.
- **The guard goes by the first character**, and a text with a space before its `=` is not
  changed. LibreOffice 25.8 takes ` =1+1` for text (verified). A spreadsheet that strips
  spaces before deciding would still run it; none of the three is documented to.
- **The guard's rule is a judgement.** It guards `- call mum (tomorrow)` because of the
  parenthesis, and leaves `+1-555-0100` alone although Excel may calculate it (which
  changes what is shown and can do nothing). The table above is the whole rule.
- **The byte-order mark by default** is a judgement for spreadsheets. A script that reads the
  file as plain UTF-8 will see it in the first field name; `--no-bom` is for that.
- **XML and HTML export and XML import are not built** (the table above).
- **The single "long" table** (one row per cell) was not built; the lookup tables already
  hold every cell ID and are checked to be complete.
- **`--header-row`** drops the first row from the data of the tables it applies to, so those
  first-row cells' IDs are not in the export; the default loses nothing. Its column names
  come from cell text and can be anything (they are quoted and guarded like any field).
- **`row_id` depends on the first cell of the row** (above). Rows with IDs of their own would
  be a change to the model.
- **A lookup folder is not replaced as one step.** With `--overwrite` the tables of the
  export before are removed and the new files written one by one, the index last; a crash
  in between leaves a folder that needs another export with `--overwrite`, or, if it was
  new and has no index yet, removing by hand.
- **Between the check and the write** another program can still act: a file is safe (it is
  renamed into place, which follows no link), but a folder swapped for a link at that moment
  would be written into, and a file put at the name of a table in that moment is replaced
  whatever it is. Closing that needs calls the standard library does not have.
- **Reading is not hardened as writing is.** A FIFO given as the file to import, or as a
  document, makes the tool wait for whoever writes to it. Nothing is written.
- **The exports take the whole grid of a cell**, not a selected block of it, and hold the
  whole text in memory (at most 512 MiB; a lookup export at most 10,000 tables).
- **The delimiter of a `.csv` file is looked for, and can be wrong.** A file of one line, or
  one in which both comma and semicolon make a table and the commas are not decimal commas,
  is read by commas; the tool says which delimiter it used, and `--delimiter` settles it.
  Only UTF-8, UTF-16 and Windows-1252 are read; a file in another old encoding has to be
  converted first.
- **A first cell whose text starts with the character U+FEFF** is quoted in delimited text so
  that it is not taken for a byte-order mark; in indented text with the root's own line it
  would be lost on import.
- **The tool calculates as after loading** (`Calc::new`): a formula that reads a variable of
  a program run exports as `#N/A` unless the caller exports from an editor after a run.
- **Paste of text** as TreeSheets does it (merging into the surrounding grid) is not built.
- **Excel's own "Unicode text"** (UTF-16 with a byte-order mark, tabs) is decoded, but no
  such file from a real Excel was tried.
- **The count of error values** that an export prints is of formula cells whose result is
  an error. A data cell whose text happens to be `#N/A` is not counted.

## Together with the fixes after review of milestones 4 and 5

The fixes (see the ends of `M4.md` and `M5.md`, decisions A80 to A89) were made on the

- **Flatten and the flattened export both go by what formula cells show.** `Flatten`,
  `Hierarchify`, `Collapse` and hierarchy swap now take the result of a formula cell
  (A83), as the exports always did (A96). The random test that compares the flattened

Two things were done differently from what the review proposed, or need saying:

- **`error_cells` is a function beside the exports**, not a second value that every export
  returns: the exports keep returning their text, and the count is asked for with the same
  source and cell.
- **Writing a lookup folder into a temporary folder and renaming it into place was not
  done.** It works only for a folder that is not there yet; where it is needed, on
  overwriting, a folder that is not empty cannot be renamed over. The limitation is
  documented under "Writing files safely".

### What changed for a user

- Exported CSV has more fields in quotes (those with `;` or a tab), and fewer with a `'` in
  front. A flattened export of a document with a row of several nested grids has parent
  columns at the end unless `--no-parent-columns` is given. `--treesheets` exports are byte
  for byte as before.
- `wombat import` refuses a file that is not UTF-8 (or UTF-16 with a mark) unless
  `--encoding` says what it is; finds the delimiter of a `.csv` file; and says what it read.
- `import CELL FILE` in `wombat edit` refuses to replace a grid with content without the
  word `replace`.
- `--overwrite` on a lookup folder removes the tables of the export before, and refuses a
  folder that is not a lookup export.

### Verified in a real spreadsheet

`referee/exports/check_lookup_libreoffice` (optional; no test needs it) was run with
LibreOffice 25.8.7.3, headless, with the settings its import dialog proposes for a CSV file
(separated by comma, semicolon and tab; text delimiter `"`; UTF-8; "detect special numbers"
off). The document: three projects, two with tables inside, with the texts `Ana; Bob`,
`say "hi", twice`, `x,y`, `日本語`, `東京 プロジェクト`, `- item one`, `+44 20 7946 0958`,
`@handle`, `=1+1`, `+SUM(1)`, `00123`, `-5`, `12345678901234567890`, `2026-03-04`, `TRUE`,
and a note with a tab, a semicolon and a comma; exported with `--format lookup --notes`.

Result: **all 20 checks passed.**

- Each of the three tables opens as a sheet named after its file (`table-…`, `Ana-Bob-…`,
  `東京-プロジェクト-…`), arrives as the rectangle that was written, and has an ID in every
  cell of every ID column.
- The README has the LibreOffice formulas that the script types in, and in the workbook of
  the two sheets `=XLOOKUP(I2, $'table-…'.G:G, $'table-…'.A:A)` and
  `=INDEX($'table-…'.A:A, MATCH(I2, $'table-…'.G:G, 0))` give `Ana; Bob` for both rows of the
  first nested table and `東京 プロジェクト` for the three rows of the second; `COUNTIF` gives
  2, 0, 0 and 0, 3, 0.
- The texts stay as written (the guarded ones with their visible quote: `'=1+1`,
  `'+SUM(1)`), except the values listed in the table of "What a cell exports as": `00123`
  became 123, the long number 1.23456789012346E+019, `2026-03-04` a date, `-5` a number.

The same script run with the tool as it was before the fixes fails 8 checks: the row with
`Ana; Bob` and the note arrives shifted, an ID column holds a file name, and both lookups
give `#N/A`.

What LibreOffice makes of the guard's candidates was tried separately (a CSV file of 40
texts, opened with "evaluate formulas" on and off): only a field that starts with `=` is
taken for a formula; `==` and `= in prose` become errors (`Err:520`, `Err:509`), `=` alone
stays text, and everything that starts with `+`, `-` or `@` stays text or becomes a number.
A quote in front is shown as a character.

**Excel and Google Sheets cannot be run here. Everything this document says about them is
from their documentation and is unverified.**

### Mutation check of the changed code

22 faults were put into the changed code, one at a time, and the tests of import and export
run on each: the old quoting rule; `@` never guarded; a list item with a call left alone; `!`
not taken for a reference; no second quote before a quoted risky text; `unguard` taking any
leading quote; the offset of the wrong byte without the mark; UTF-16 guessed without a mark;
no decimal-comma rule; delimiters counted inside quotes; a non-regular file replaced; the
trailing separator kept; names from the old index not checked to be plain; stale tables not

renaming nothing; the parent letter without the start of its block; parent columns never
unasked; content replaced unasked; no size estimate; error values counted without asking

cells (the check that the cell is a formula is kept as a safeguard).
