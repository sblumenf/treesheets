# Milestone 1: documents and file format

Status: finished. All three checks pass (`cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`), 61 tests.

## What was built

- **The document model** (`crates/wombat-core/src/model.rs`). A document is a root cell; a cell
  has text and optionally a grid of cells. It holds everything a TreeSheets `.cts` file says
  about content: cell kind, colours, draw style, note, alignments, relative size, style, rich-text
  runs, links, last-edit time, an image reference with scale, the grid's border colour, spacing,
  vertical flag and column widths, and the document's tags. Every level also carries the fields
  the core did not recognise in a file.
- **Permanent IDs** (`id.rs`): 128-bit random values written as UUIDs, for cells and documents.
- **The `.wombat` format** (`format.rs`), specified in `docs/FILE_FORMAT.md`: readable JSON, one
  cell per line, defaults left out, byte-identical on every save, unknown fields written back.
- **View state** (`view.rs`): folded cells, selection and zoom, by cell ID, in a separate file.
- **Files** (`storage.rs`): atomic save, size-bounded reading, the image folder, view-state files.
- **Workspaces** (`workspace.rs`): list, open by name or ID, create, save.
- **The `wombat` tool** (`crates/wombat-cli`): `new`, `new --from <outline>`, `show`, `check`,
  `list`.

## How to try it

From `wombat/`:

```sh
cargo build
printf 'Shopping\n  Fruit | Price\n  Apple | 1.20\n    red\n    green\n  Pear | 2\n' > /tmp/shop.txt
target/debug/wombat new /tmp/shop.wombat --from /tmp/shop.txt
cat /tmp/shop.wombat             # or open it in a text editor
target/debug/wombat show /tmp/shop.wombat
target/debug/wombat check /tmp/shop.wombat
target/debug/wombat new /tmp/empty.wombat
target/debug/wombat list /tmp
```

In an outline, each line is a row, ` | ` separates the cells of a row, and lines indented under a
row become the grid inside that row's first cell.

## Design choices (details in `DECISIONS.md` A16-A22, B8-B13)

- **In memory**: one hash map from cell ID to cell; each cell records its parent; a grid holds the
  IDs of its cells. Looking up a cell or its parent by ID is one map lookup at any document size,
  which is what commands addressed by ID (milestone 3) need. The alternative, cells owning their
  grids directly as TreeSheets does, would need a second index kept in step with the tree. The
  cost is one map lookup per step when walking the tree.
- **Low-level layer**: `Document::new`, `add_grid`, `cell_mut` and `Cell::grid_mut` are the only
  ways to change a document for now. A cell's ID, parent and grid shape cannot be changed from
  outside the crate; text and properties can, and `Document::validate` (run by every save and
  load) checks them. Milestone 3 builds commands on top and should then stop exposing `cell_mut`.
- **Versions**: a newer major version is refused; a newer minor version loads, because minor
  versions may only add fields.
- **Strict loading**: a file is valid or refused; nothing is repaired or skipped.

## Measurements

One document of 101,001 cells (three levels, text in every cell, runs and links on a tenth of
them), 14.2 MB as a file, on this development container:

| Step | Debug build | Release build |
| ---- | ---- | ---- |
| Save to text | 0.39 s | 0.12 s |
| Load from text | 0.97 s | 0.33 s |
| Save to file (atomic, synced) | 0.57 s | 0.15 s |
| Load from file | 1.05 s | 0.38 s |

The test only fails above 60 seconds per step, so it will not flake; it prints the times.

## Tests

- 33 unit tests (IDs, model rules, the exact file text, every kind of refusal, view state).
- 9 property tests, 256 cases each: save then load gives an equal document; saving is
  deterministic (also across rebuilt documents and reloads); unknown fields added to every object
  of a file survive load and save; arbitrary bytes, arbitrary JSON, byte-damaged valid files and
  structure-damaged valid files never panic, and anything that does load is a sound document
  that saves and reloads equal; view state round trips.
- 10 file tests (atomic save, leftover temporary file, size limit, images, view state,
  workspace), 1 large-document test, 3 outline tests and 5 tests that run the real `wombat`
  program.

## Dependencies

- `wombat-core`: `serde_json` only (which brings `serde_core`, `itoa`, `memchr`, `zmij`).
  `cargo check -p wombat-core` was run and passes for `wasm32-unknown-unknown`,
  `aarch64-linux-android` and `aarch64-apple-ios`. That shows it compiles there, not that it
  runs: in a browser there is no file system, so `storage.rs` would return errors and an
  interface would call `format::to_string` / `format::from_slice` with its own storage.
- `wombat-cli`: `getrandom`, to seed IDs from the operating system. Not needed by the core.
- Tests only: `proptest`.
- No UUID crate: writing and reading the UUID text is about 40 lines, and generating IDs inside
  the core would have meant the core reading randomness, which the rules forbid.

## Not done, doubtful, or different from the brief

- **ID generation is a hand-written xoshiro256\*\* generator** seeded with 32 random bytes per
  run of the program, instead of a UUID library. Uniqueness rests on that seed. The IDs are not
  unpredictable (not a security feature).
- **Copying a `.wombat` file by hand duplicates all its IDs**, breaking "unique across all
  documents". Nothing detects or repairs it; `Workspace::open_id` opens the first match by name.
- **`Workspace::list` loads every document completely** to learn its ID. Fine for tens of
  documents, slow for thousands of large ones. An index or a cheaper header read is future work.
- **Memory while loading** is bounded but not small: the file is first parsed into a generic JSON
  tree, then converted. Expect several times the file size; a file at the 256 MiB limit could
  need a few gigabytes. A streaming reader would fix this and was not attempted.
- **Nesting is limited to 32 levels** (decision A20). A deeper `.cts` file cannot be imported.
- **Unknown fields are kept as values, not bytes** (A19); very large numbers in them lose
  precision.
- **Atomic save** was tested for: no leftover temporary file, old file intact when the save is
  refused or the rename fails, a stale half-written temporary file being harmless. It was *not*
  tested against a real power cut or a full disk, and only on Linux. Two programs saving the same
  file at once are not protected from each other (fixed temporary name, no locking).
- **Images**: the core copies a file in and refers to it by name. "Save as" does not take the
  images along by itself (`storage::copy_images` must be called), unused image files are never
  deleted, and the CLI has no image command.
- **Runs and links are checked only against the text length in code points.** Nothing yet stops
  a range from splitting an emoji made of several code points; A11 puts that on the editing
  commands of milestone 3.
- **View state** is saved and loaded but nothing uses it yet; whether "top-left cell plus size"
  is the right shape for a selection will only show in milestone 3.
- **The outline input of the CLI** is deliberately crude: no way to write a cell containing
  ` | `, and a nested grid can only hang under the first cell of a row.
- **The referee was not used**: nothing in this milestone has behaviour TreeSheets defines. The
  model's field list was taken from `TS/docs/file_format_spec.txt` and the C++ headers by reading.
- **Property tests run 256 cases each** (about 16 seconds in total). That is a smoke level of
  fuzzing, not proof; no coverage-guided fuzzer was run.
- The CI file (`.github/workflows/wombat.yml`) is outside `wombat/` and was not touched.

## What milestone 2 should know

- Build documents with `Document::new`, `add_grid` and `cell_mut`, then call `validate`.
- TreeSheets colours are blue-green-red numbers; convert to `Color::rgb`. Run colours carry a
  "has colour" bit (bit 24).
- A TreeSheets image has one scale; copy it to every `ImageRef` that uses the image. Write image
  bytes into `storage::images_dir(path)` under a valid name (`is_valid_image_name`).
- `folded`, the selection and the zoom level go into a `ViewState`, not the document.
- TreeSheets internal links name a cell by its text; resolve each once (decision B1) into
  `LinkTarget::Cell`. If no cell matches, there is no good target: decide then, and record it.
- TreeSheets drops invalid runs and links when reading; the importer must do the same *before*
  building the document, because Wombat refuses them.
- `vertical` lives on the grid (TreeSheets: on the cell, saved in the grid part of the file).
- Column widths default to 80 here; TreeSheets writes one per column, so copy them all.
