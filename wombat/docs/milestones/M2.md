# Milestone 2: TreeSheets importer

Status: finished. All three checks pass (`cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`), 118 tests
(61 from milestone 1, 57 new) and 1 that only runs by hand.

## What was built

- **A new crate, `crates/wombat-cts`**: `import(bytes, ids)` reads a TreeSheets `.cts` file and
  returns a Wombat document, its view state, its images and a short account of what happened
  (format version, links without a target, texts that were not UTF-8, nesting depth, the
  auto-export setting). `Imported::save` writes the `.wombat` file, the images that cells show
  and the view state, in the layout of milestone 1.
- **Every format version up to 31**, following TreeSheets' own loader rather than the written
  specification. Versions 6, 7, 8, 13, 15, 17, 19, 23, 24, 28, 30 and 31 are checked against the
  real app; the others (1-5, 9-12, 14, 16, 18, 20-22, 25-27, 29) only against files this code
  built itself.
- **Links by text resolved to links by ID** (decision B1) with TreeSheets' rule: breadth first
  in the grid of the linking cell, then in each grid around it, never the linking cell or the
  root. It is done from an index, so a file with very many links does not take links-times-cells
  time.
- **`wombat import <file.cts> <file.wombat>`**, and `wombat show` now also takes a `.cts`
  directly and marks folded grids.

## How to try it

From `wombat/`:

```sh
cargo build
target/debug/wombat show ../TS/examples/tutorial.cts | head -30
target/debug/wombat import ../TS/examples/tutorial.cts /tmp/tutorial.wombat
target/debug/wombat show /tmp/tutorial.wombat | head -30
target/debug/wombat check /tmp/tutorial.wombat
ls /tmp/tutorial.wombat.images /tmp/.wombat-view
target/debug/wombat import referee/fixtures/features.cts /tmp/features.wombat
grep cts_target /tmp/features.wombat      # the one link whose target does not exist
```

## The comparison with the real TreeSheets

`crates/wombat-cts/tests/referee.rs` imports each file and compares it with the dump the real
TreeSheets made of the same file. Nothing is special-cased per file.

- **The 37 examples and the fixture: 38 files, 8,198 cells, no mismatches.** Compared for every
  cell: type, text (8,030 cells; for the 168 formula cells the formula instead, because the
  dump's text is the calculated result), note, both colours, relative size, style bits, both
  alignments, render style, has-image, last-edit time, tag or not, and the style, colour and
  link of every code point (which covers runs and links whatever way they are split). For each
  of the 1,526 grids: size, border colour, column widths, folded (from the view state) and
  vertical layout. Per file: format version, cell count, the selection's place and size, the
  auto-export setting.
- **11 "quirk" files, 83 cells, no mismatches.** The first comparison passed on the first run,
  and switching off parts of the importer showed why that proved less than it seemed: at least
  four behaviours taken from reading the C++ were exercised by no example (a cell without
  text taking its parent's size, the minimum column width, a fold removing a cell's image in
  versions 16-17, and zoom). So `tests/quirks/` has hand-built files for these and for the
  last of several selection marks winning, the "=" added to a formula, control characters in
  tag names, repaired runs and links, text that is not UTF-8, odd alignments and image numbers,
  version 6, 8 and 17 layouts and six selection/zoom cases. The real TreeSheets read all eleven
  and its dumps are checked in beside them. With them, each of nine deliberate breakages of the
  importer makes the comparison fail.
- **Internal links**: the test also searches the *golden* tree with TreeSheets' rule written
  out naively and requires the importer's target to be the same cell. Only 4 internal links
  exist in all golden data (2 of them resolve); the rule itself rests mostly on the hand-built
  unit tests and on a property test of the index against the naive search (200 random trees).

### What could not be compared

- **Image bytes, image type and display scale**: the dumps only say whether a cell has an image.
  Tests check that saved images are whole PNG files (signature and end chunk), not their pixels.
  The scale's encoding was read from wxWidgets' source and from the files (see below).
- **Tag colours and the tag list**: only "this cell's text is a tag" is in the dumps. Tags no
  cell uses, and all tag colours, are unverified. The default colours for files before
  version 24 (white, blue text) come from the C++.
- **Grid outer spacing**: it is in the referee's `.xml` kind, which the test does not read.
- **Which grid the selection is in, and the zoom** itself: the dumps have the selection's
  column, row and size only. Zoom is checked indirectly, where it moves the selection.
- **Vertical layout of cells without a grid**: Wombat keeps it on grids only (decision B10).
- **The text of formula cells** as TreeSheets shows it (the result): milestone 5.
- **JPEG images** in files older than version 22, which have no stored length: no example has
  one. The importer finds the end by stepping through the JPEG's markers; TreeSheets by decoding
  it. Tested on a hand-made byte sequence only. Doubtful.

## What the file format really is (differences from `TS/docs/file_format_spec.txt`)

- **A string** is a 32-bit little-endian byte count, then UTF-8 bytes, no terminator. Bytes that
  are not UTF-8 load as an empty string in TreeSheets (confirmed with a quirk file); the importer
  does the same and counts them. No example has one.
- **The image scale is 10 bytes, not a `double` of 8**: wxWidgets writes an 80-bit extended
  number, most significant byte first. `3f ff 80 00...` is 1.0, `40 00 c0 00...` is 3.0.
- **Colours** are `0xBBGGRR` numbers, red in the lowest byte (confirmed).
- **`lastedit`** is milliseconds since 1970 UTC (confirmed).
- **The tag list can end with the file** instead of an empty name: an example of version 24 does.
- **TreeSheets cannot open a file older than version 9 with two or more PNG images**: its loader
  switches to big-endian while stepping over the first image and never switches back. Tried
  with the real app. The importer refuses such a file too. This looks like a bug in TreeSheets;
  it was not reported or changed.

## Nesting depth

The deepest example is `contrib/Procrastination.cts` at **15** levels; the tutorials are 8. The
limit of 32 (decision A20) was not changed. A `.cts` nested deeper is refused with "over a
limit: grids nested deeper than 32"; TreeSheets itself allows 500. The reader does not recurse,
so depth costs no stack in the importer; the limit is the core's.

## Tests

- 45 unit tests in the crate (and one that only writes the quirk files, run by hand): string and number
  decoding; every version from 1 to 31 reading exactly the fields it has, and not reading like
  its neighbour; refusal of password-protected files, newer versions and other data; repair of
  runs and links; link resolution (same grid, nested grid, enclosing grid, duplicates at
  different distances, missing target, own cell and root); selection and zoom; images; limits.
- 7 fuzz-style tests: arbitrary bytes; arbitrary bytes after a valid header; an arbitrary cell
  stream properly compressed; every example and quirk file truncated, bit-flipped, with numbers
  overwritten and bytes removed or inserted, both as a file (2,000 cases) and inside the
  decompressed cells, compressed again (2,000 cases); every file cut at every length through
  its header and at steps beyond.
  Whatever still imports must pass `validate` and survive the `.wombat` format. 1,588 of 1,912
  one-bit changes to cell streams still import, so the cell reader really is reached.
- 3 referee tests (above; one also saves every file as `.wombat` with images and view state and
  loads it back equal, and checks that the same seed gives the same IDs).
- 2 new tests of the `wombat` program.

## Changes to `wombat-core`

None to the code. `docs/FILE_FORMAT.md` gained a paragraph on the `cts_target` field, which the
core treats as any unknown field. The model held everything a `.cts` carries except the
auto-export setting, which was left out on purpose (decision A25).

## Dependencies

`wombat-cts`: `miniz_oxide` 0.8 (brings `adler2`). `cargo check -p wombat-cts` passes for
`wasm32-unknown-unknown`, `aarch64-linux-android` and `aarch64-apple-ios`: it compiles there;
nothing was run there.

## Not done, doubtful, or different from the brief

- **A link's target is fixed at import.** TreeSheets looks again every time, so there a link
  starts working when a cell with the text appears. Here a link without a target stays so, with
  its text kept (decision B14).
- **Formula cells are never link targets** (decision B15), because TreeSheets matches their
  calculated result, which the importer does not have. No example links to a formula cell, so
  this has cost nothing yet, but it is a real gap until milestone 5.
- **`wombat show` decides by file name** (`.cts`) whether to import, not by content, so that a
  damaged `.wombat` file is still reported as one.
- **The importer is stricter than TreeSheets** about damage (decision A23): TreeSheets opens
  some truncated files that the importer refuses.
- **Memory**: the limits bound it but not tightly. A hostile file of a few hundred kilobytes can
  make the importer allocate the 256 MiB decompression limit, and a 256 MiB stream of minimal
  cells can reach the core's 5,000,000-cell limit, which in memory is well over a gigabyte.
  Nothing is unbounded, and a grid's cells are only made once the data for them is seen to be
  there, but "bounded" is not "small".
- **The fuzzing is a smoke level**: a few thousand random cases per run, no coverage-guided
  fuzzer. It found nothing; that is weak evidence.
- **Unknown style bits and old image names are dropped** (decision A25). No example has either.
- **Saving is not one atomic step**: the document is written first, then the images, then the
  view state. A failure in between leaves a valid document with images missing, which
  `wombat check` reports.
- **The quirk files' golden data** were made with this checkout's build of TreeSheets. Like the
  referee's, they have to be made again if the loader changes; `tests/quirks/README.md` says how.
- **The CI file** is outside `wombat/` and was not touched; it already runs the whole workspace.

## What milestone 3 should know

- `wombat_cts::import` with a `SeededIds` gives 49 ready-made documents (38 + 11) for tests of
  commands and undo, with realistic runs, links, images and deep nesting.
- The importer still uses `Document::cell_mut` and `add_grid`. If milestone 3 hides `cell_mut`,
  it needs another way to build a document in bulk.
- Imported text never has control characters (decision B12 leaves open what editing does).
- Imported view state is the first real use of `ViewState`; "top-left cell plus size" was enough
  to hold what TreeSheets saves.
