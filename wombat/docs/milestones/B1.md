# Milestone B1: a minimal bridge between Flutter and the Rust core

("Milestone B1" is the bridge work of `NEXT_BRIDGE.md`. It is not decision B1, "Links point at
cell IDs", in section B of `DECISIONS.md`.)

Status: **built, run on Linux, built for Android, and reviewed; not finished by the brief's
definition.** What is left needs an Android device and is listed under "Left to do": running
the app on Android and the measurements there. The independent review was done; what it
found and what was done about it is under "Fixes after review", and what is still open after
that under "Still open after the fixes". Everything else that `NEXT_BRIDGE.md` asks for is
here and passes. Decisions A122 to A131 are from the milestone and A132 to A148 from the
review; there are no new departures from TreeSheets, so nothing was added to section B. The
file format did not change.

A bare Flutter app now opens a real Wombat document through the Rust core, shows it as text,
changes one cell, shows what the core says changed, and undoes it.

## What was built

- **Three additions to the core**, each with tests (`crates/wombat-core/tests/read.rs`):
  - `Editor::grid_view`: one cell and the cells of its grid, each with its text, kind, what a
    formula cell shows, whether that is an error value, and whether it has a grid (A125).
  - `Clip::as_document` and `Clip::from_document`: a clip leaves the program as a document
    and comes back checked, so that the two paste commands can be serialised without opening
    a way to make cells that break the model's rules (A124).
  - A test that `Editor`, `Clip`, `Command` and `Error` can move between threads.
- **The bridge crate** `crates/wombat-bridge` (package `wombat_bridge`), about 1,800 lines
  written by hand and 3,300 generated:
  - `api/document.rs`: `OpenDocument`, the handle Dart holds. Open a file, create one, open
    a copy with fresh IDs; the ID of the document and of its root; read one grid; apply one
    command; undo; redo; save. Every one returns a value or an error value. (After the
    review: also overwrite and close, see "Fixes after review".)
  - `api/wire.rs`: the serialised form of all 45 commands, of change reports (with the
    recalculated formula cells, A126) and of errors (A123, A129).
  - `convert.rs`: between that form and the core's types, checking on the way in.
  - `record.rs`: the same form as JSON text, to record commands and play them back.
- **The bare app** `app/`: one screen of plain text and three buttons, Open, Change and Undo.
  Open copies the example that comes with the app (`assets/example.wombat`, 14 cells, two
  nested grids and a formula) and prints the root grid and the grids inside it. Change sets
  the text of one cell and prints the change report and the grids again. Undo undoes.
- **Tests without a device**, in both languages (see "Tests"), and a second job in
  `.github/workflows/wombat.yml` that runs the Dart ones. (After the review: three jobs,
  see "Fixes after review".)
- After the review, `app/lib/session.dart`: the one Dart class through which the app and its
  tests reach a document, which sends the calls in the order they were made (A144).

## How to try it

On a machine with Rust (rustup) and Flutter 3.47.9. On Linux the desktop build also needs
`libgtk-3-dev`.

```sh
cd wombat
cargo test -p wombat_bridge          # the Rust side
cd app
flutter pub get
flutter test                         # the Dart side, calling the real core
flutter run -d linux                 # the app; the bare screen is "Bridge check" in the menu
```

(`flutter test` builds the bridge's library itself before it loads it, with
`cargo build -p wombat_bridge`; see `app/test/support.dart`.)

On a machine without a screen, the real app is run and its buttons pressed by:

```sh
xvfb-run -a flutter test integration_test/app_test.dart -d linux
```

One file for each run: the whole folder at once (`flutter test integration_test -d linux`)
fails with "Error waiting for a debug connection" since there is more than one file in it.
All of them, as CI runs them:

```sh
for test in integration_test/*_test.dart; do xvfb-run -a flutter test "$test" -d linux; done
```

A recorded command looks like this (`record::command_to_json`):

```json
{"SetText": {"cell": "00000000-0000-0000-0000-000000000001", "text": "new"}}
```

## Measurements (Linux desktop)

Taken by `app/lib/measure.dart` through `app/integration_test/measure_test.dart`, on the
Linux x86-64 cloud machine (4 cores, under Xvfb, software rendering), in **profile mode**:
Dart compiled ahead of time, the Rust library built with `--release`. **These are desktop
numbers, not phone numbers.** A debug build is about three to four times slower and is not
shown.

The document is the shape of the one in `crates/wombat-core/tests/large.rs`: 101,001 cells,
a root grid of 10 by 100 whose cells each hold a grid of 10 by 10, 12.9 MB as a file. It is
built on the spot with one `Import` command. One innermost cell holds a formula that reads
every cell of the document, so that an edit includes a recalculation; a second pass without
that formula shows what the command and the bridge cost alone. Each timing is 5 runs in
one process; two separate processes agreed within a few percent, and the first is shown.

| Step, end to end from Dart | Median | Worst |
| ---- | ---- | ---- |
| Open the document | 615 ms | 690 ms |
| Read the root grid (1,000 cells) | 2.9 ms | 4.2 ms |
| Read an inner grid (100 cells) | 1.5 ms | 1.7 ms |
| Set the text of one cell, with the formula | 40.5 ms | 41.2 ms |
| Insert a row in the root grid, with the formula | 78.6 ms | 83.0 ms |
| Set the text of one cell, no formula | 1.4 ms | 1.4 ms |
| Insert a row in the root grid, no formula | 1.4 ms | 1.6 ms |
| Save | 207 ms | 229 ms |

Undoing each edit takes as long as the edit.

| Resident memory of the app | MiB |
| ---- | ---- |
| Before opening (the app alone) | 208 |
| After opening | 381 |
| Peak while opening | 414 |
| At the end, after 5 opens, the edits and 5 saves | 752 |

What they say:

- **The bridge itself costs about a millisecond a call.** An edit that nothing depends on is
  1.4 ms from Dart and back.
- **Opening takes about 0.6 s**, against 0.38 s for the core's load alone in milestone 1:
  opening also checks the document and works out the formulas.
- **Opening costs about 206 MiB at its peak over what the app takes alone, for a 12.9 MB
  file: about 16 times the file.** A file at the 32 MiB limit would be near 500 MiB, which
  many phones do not give an app. This is the known concern of `POC_SUMMARY.md`, now with a
  number from inside an app. Nothing was done about it here.
- **An edit is slow when a formula reads the whole document:** 40 ms for a text, 80 ms for
  a row, nearly all of it recalculating (`M5.md`: everything is worked out again after a
  structural change). 80 ms is five frames at 60 Hz on a desktop processor; a phone will be
  slower. The calls run off the thread that draws, so the screen does not freeze, but the
  result arrives late.
- **Memory grows when a document is opened again and again in one process** (381 MiB after
  one open, 650 to 750 after five). It did not look like a leak: with glibc told to use one
  arena (`MALLOC_ARENA_MAX=1`) a throwaway run stayed level over eight opens. glibc keeps a
  heap per worker thread. Android has a different allocator, so look at this there.

  32 MiB limit may be killed by the system, which no error value can report. No lower limit
  was set here.
- That generated code is up to date is checked by CI since the review (it runs the generator
  and compares), on Linux with generator 2.13.0 only. Still regenerate after every change to
  `api/` (`../AGENTS.md` says how); CI only tells you when you forgot.
- macOS and Windows desktop builds. `rust_builder/` has their build files as
  `flutter_rust_bridge` generated them; the app was created for Linux and Android only.
- Calls that overlap were not tried here. The review tried them: they are kept apart but
  not in order (A127). The app now sends them in order from one Dart class (A144, and

- A panic crossing the bridge to Dart has no test here: it would need a function in the
  shipped library that panics on purpose. The evaluation after the review tried it in a
  copy (A129); what an open document does after a panic is tested inside the crate (A143).

## What went wrong, and what the next piece of work should know

- **The build of the app does not use the pinned Rust.** cargokit compiles the bridge with
  rustup's `stable`, whatever `rust-toolchain.toml` says (A131). On this machine the two
  were the same version. A newer stable can warn where the pin does not; warnings do not
  fail that build.
- **The package had to be named with an underscore** (A131), or the app fails at link time
  with "cannot find -lwombat_bridge".
- **Freezed.** Enums that carry data, such as `Command`, become Dart sealed classes through
  the `freezed` package, which the generator needs in `pubspec.yaml` (`freezed_annotation`,
  and `freezed` and `build_runner` as dev dependencies). Without them it stops half-way with
  a long backtrace.
- **Flutter's own names.** The mirror types avoid `Color`, `TextAlign`, `Table`, `Clip` and
  `GridView`, which Flutter has: they are `Rgb`, `HorizAlign`, `TableData`, `ClipData` and
  `GridInfo` here.
- **Every call is asynchronous**, also `id()` and `root()`: a synchronous call on a document
  that another call is working on would block the thread that draws.
- **Calls must be sent one at a time.** Two calls on one document that are both under way
  are carried out in either order (A127). `Session` in `app/lib/session.dart` does that for
  the app: use it, and never the handle `OpenDocument` itself (A144).
- **Reading is one grid at a time.** The app reads the root grid and then each grid inside
  it with a call of its own. The real grid screen will want the cells it can show, which
  the core cannot answer cheaply yet; `NEXT_BRIDGE.md` leaves that to the next piece.
- **Dart cannot get a clip yet.** The paste commands are in the serialised form, but no call
  gives a clip to Dart (`convert::clip_out` exists on the Rust side). Copy and paste need it.
- **Typing and groups are not bridged** (`apply_typing`, `begin_group`, `end_group`), nor
  search, links, the program's report, import from a file or export.

## Fixes after review

The independent review (`../NEXT_REVIEW.md`) found the following. Each fix began with a test
that failed because of the finding, unless its entry says otherwise.

- **A clip carried its source twice** (finding 5, A132). `ClipData.source` and the ID of the
  carried document could differ, and `source` won silently. Test:
  `the_source_of_a_carried_clip_is_the_id_of_its_document` (`roundtrip.rs`) carries the same
  cells as a document with another ID and expects that ID as the source; it failed with the
  old one. `ClipData.source` is gone and `Clip::from_document` takes two arguments. In the
  core, `tests/read.rs` pins the source, and builds two unchecked documents whose clips
  `Clip::as_document` must refuse, so the check there is not dead code as the review
  suspected.
- **One kind of error meant two things** (finding 8, A133). `ErrorKind::Invalid` was both a
  broken file and a malformed request. Tests: `what_cannot_be_a_command_is_refused_as_a_value`
  and the two session tests (Rust and Dart) now expect `BadRequest` for what the bridge
  refuses and `Invalid` for what the core does; they did not compile before the kind existed.
  A list of every kind, which does not compile when one is added, replaces the hand-kept
  list of the JSON test.
- **Whole numbers from Dart were cut to 32 or 8 bits without a word** (finding 2, A134).
  Test: `app/test/wire_test.dart` asks for a row inserted at 4294967296 and expects
  `BadRequest`; before, the row was inserted at 0. In Rust, `numbers_out_of_range_are_refused`
  goes through the edges of each range, and `every_number_of_a_command_is_checked` puts a
  number out of every range into each whole number of random commands in turn. The mirror
  types carry `i64` and `convert.rs` checks the range.
- **A deeply nested table to import ended the process** (found by the evaluation after the
  review, A135). The serialised form was a table within a table, and the generated decoder
  and the conversion recursed without a bound: a stack overflow, which no error value or
  caught panic reports. Tests: `crates/wombat-bridge/tests/deep.rs` converts a table nested
  100,000 deep on a 2 MiB stack and expects `Limit` (it aborted the test process before),
  and `app/test/wire_test.dart` imports one through the real library (the Dart test process
  died at depth 5,000 before). The form is now one flat list; `measure.dart` builds its
  document in that form.
- **The generated file was let off more lints than it needs** (evaluation, A122). `lib.rs`
  allowed six for `frb_generated`; only `unsafe_code` and `clippy::unwrap_used` are needed.
  Checked with clippy: it passes with the two, and fails without either. A122 named
  `missing_docs` wrongly and is corrected.
- **The JSON form took incomplete and misspelt commands** (finding 4, A136). Tests:
  `json_that_leaves_a_field_out_or_adds_one_is_refused` by example (it failed on
  `SetRangeColor` without `color`, which was read as "remove the colour"), and
  `every_field_of_a_command_is_needed_and_no_other_is_read`, which takes each field in turn
  out of random commands as JSON, or adds one. `{"Run": null}` is still read as `"Run"`,
  on purpose, and the test says so. A Dart test shows that `null` still crosses as none.
- **The comments of the serialised form left out rules that the core states** (finding 8).
  They become the documentation of the Dart classes and are all a Dart developer sees. The
  comments of `Command`, `Prop`, `Report` and the types they hold in `api/wire.rs` now say
  what the core's say: control characters become spaces, positions are code points and must
  not cut a user-perceived character, a command that asks for nothing new succeeds with an
  empty report, what each command refuses, the ranges of numbers and the limits. The
  generator drops the comment of an enum that holds data, so those rules are on the
  variants, the fields and `Report` (A137). Nothing
  tests a comment; `cargo doc` with warnings denied resolves every link in them.
- **Half a surrogate pair in a Dart string arrives as U+FFFD without notice** (finding 6).
  Not changed: Dart's own encoder does it before Rust sees the string, and refusing would
  mean checking every string on the Dart side. It is documented at the top of `api/wire.rs`
  and pinned by `half a surrogate pair arrives as U+FFFD` in `app/test/wire_test.dart`
  (cell text, a note, an ID, a path). That test passed when written: it pins behaviour
  that was there, it did not fail first.
- **Mutations that no test noticed** (finding 7, the part in `convert.rs` and the core).
  `crates/wombat-bridge/tests/out.rs` is new. Each of these was made by hand, seen to fail a
  test, and put back: `removed` filled from `grids`, `tags` always empty, `created` and
  `recalculated` filled from `changed` (`report_out`); `failed` always false (`cell_out`);
  `Limit` as `Refused`, `NewerVersion` as `WrongFormat`, `HalfSaved` as `Io` without a path
  or with the wrong file, `AlreadyExists` without a path (the error mapping, now a list over
  every error of the core); the finite check of an image's scale dropped (`image_in`).
  These tests passed when written: they are there to fail under the mutations. The two
  that the review thought might be dead code: `doc.validate()` in `Clip::as_document` is
  not (see the first entry), and the test on a cell's kind in `edit/read.rs` was, because
  the results are kept for formula cells only; it is removed, and the rule test in
  `tests/read.rs` now holds that for the cell of a view as well as for the cells in it.
- **Finding 3c, the core's part: knowing that a file was changed by someone else** (A138).
  The bridge had no way to tell whether the file of an open document was still the one it
  read or wrote. Tests: `crates/wombat-core/tests/storage_bridge.rs`, module `file_state`
  (untouched file; deleted; replaced by a new file of the same length with the old time put
  back; appended to; rewritten in place; replaced through a symbolic link and the link made
  to lead elsewhere; save then check; and one test that writes down the blind spot: the same
  file rewritten in place with the same length and time is not noticed). Changed:
  `storage.rs` has `FileState`, `FileCheck`, `FileState::check`, `load_document_with_state`,
  `save_document_with_state` and `copy_document_with_state`. On Windows the check sees
  length and time only; it was compiled for Linux, Android, iOS and the web, and run on
  Linux only.
- **Not looked at by the review: a copy failing half-way** (A139). When `copy_document`
  could not save the document after copying its images and view state (or could not copy
  all images), the image folder, the pictures and a view-state file for a document that does
  not exist were left behind. Tests: the three `a_copy_…` / `a_failed_copy_…` tests in
  `storage_bridge.rs`, which make the save fail by a folder at the temporary file's name and
  the image copy fail by a name too long for its temporary file. Changed: a failed copy
  removes the files and folders it made and nothing that was there before.
- **Saving trusted its flag and never looked at the file** (finding 3c, A140). After the
  file of an open document was deleted or replaced by another program, `save()` answered
  success and wrote nothing; with something to save it went over whatever was there. Tests:
  `crates/wombat-bridge/tests/disk.rs`, one test for each case of the table in A140 (five
  of them failed before the fix: both cases of a changed file, the saved document whose
  file is gone, a link that leads nowhere, and a new document and a copy knowing their
  files), and `overwriting_is_asked_for_by_name`. Changed: `OpenDocument` keeps the
  `FileState` of its file; `save()` writes a file that is gone and refuses one that was
  changed with the new `ErrorKind::ChangedOnDisk`; `overwrite()` is new.
- **Mutations that no test noticed** (finding 7, the part in `api/document.rs`). Tests in
  `disk.rs` that passed when written and are there to fail under the mutations:
  `a_command_that_changes_nothing_leaves_the_document_saved`,
  `undo_and_redo_make_the_document_unsaved` (which also pins that undo and then redo after a
  save say unsaved), `saved_and_the_file_untouched_is_not_written_again` (seen through the
  file's number on Unix, since every save puts a new file under the name) and
  `a_new_document_does_not_go_over_a_link_that_leads_nowhere`. Each of the review's four
  mutations was made by hand, seen to fail its test, and put back: unsaved after a command
  that changed nothing, undo and redo not clearing the flag (each on its own), the guard in
  `save` dropped, `symlink_metadata` replaced by `exists`. So were six of the new code:
  a changed file written, a saved document's gone file not written, the state of the file
  not kept after a save, the flag not set after a save, the error without its path, and
  `apply` not clearing the flag.
- **Two handles on one file saved over each other** (finding 3b, A141). Tests:
  `crates/wombat-bridge/tests/open_files.rs`: a second open is refused and the file is
  free after the first is dropped; nothing is created or copied where a document is open,
  also when its file is gone; other spellings of the path (`..`, `.`, a link to the folder,
  a link to the file, a relative path) are the same file; eight threads opening or creating
  one file at once, 50 rounds each, of which exactly one wins; all five failed before the
  fix. Two more passed from the start and guard against refusing too much (another file of
  the same name, copying from an open document), and one that an open that failed holds
  nothing (it passes without the fix too, and fails when a failed open is made to keep
  its claim). Two unit tests in `src/open_files.rs`: a bare file name, and a lock that
  a panicking thread left poisoned. Mutations made, seen to fail and put back: each of the
  three constructors not claiming, the claim not given up, each of the three steps of
  naming a file left out, the poisoned lock unwrapped, and check and claim done as two
  steps. Changed: the new kind `ErrorKind::AlreadyOpen`; `tests/session.rs` and

## Still open after the fixes

Known, and left as it is on purpose or for want of a device or a decision:

- **The app is not ready to be released, by the defaults of its template**, which are the
  owner's to decide and were deliberately not changed: the application ID is
  `com.example.wombat_app` (`app/android/app/build.gradle.kts`, `app/linux/CMakeLists.txt`),
  the release build is signed with the debug key, the label is `wombat_app`, and
  `allowBackup` is not set, which means on.
- **Nothing has run on a real phone**, or on Android or iOS at all. CI builds the debug
  package for Android arm64 and runs nothing. So also untried: what Android does to the
  app when it is put away (the saving of A145 was run on Linux and by the test binding's
  own lifecycle events), the on-screen keyboard, and the measurements.
- **Windows and macOS are unverified**: no build, no test. On Windows the check whether
  another program changed the file is weaker (length and time only, A138).
- **Where the app keeps its document is the system's temporary folder** (A148), which the
  system may clear. If the file there cannot be opened, the app shows the error at every
  start and offers nothing; there is no screen for choosing or making a document.
- **The editor's text is in the document only when it is entered** (the tick, Return, a
  tap elsewhere, the app put away). An app killed outright loses it, and up to a second
  of entered changes (A145).
- **After a hot restart while developing**, the document may be refused as already open:
  the library stays in the process with its list of open files (A141) and the old handle
  is gone without a close. Not looked into.
- **`{"Run": null}` is read as `"Run"`** in the JSON form (A136), on purpose.
- **Reports and grid reads copy IDs and texts** (the review's finding 9, which it
  suspected and did not measure). A report is lists of 36-character IDs, and reading a
  grid copies every text of it. What was measured since, on the 101,001-cell document in a
  profile build on Linux desktop: reading the root grid of 1,000 cells takes 2.8 ms and an
  inner one of 100 cells 1.5 ms, end to end from Dart; and for an import of 100,000 cells
  the caller's own thread was held 34 to 130 ms of 464 to 736 ms (A127). A report that
  names tens of thousands of cells was not measured. Nothing was changed.
- **Error messages are English only**: the core's text, shown as it is.
- **`UI_SPEC.md` contradicts the core about line breaks**: its section 7 has "↵ Line break
  inside the cell", and cell text holds no control characters (a line break becomes a
  space). One of the two has to change; the app has no such key yet.
- **The bridge check assumes the shape of the example** (`demo.dart` takes the third cell
  of the root and the first cell inside it); on another document it would show a range
  error as text.
- **`Stage` and the screens are tested on a stand-in for the core as well as on the core.**
  The stand-in (`app/test/fake_document.dart`) knows two commands; where it and the core
  could differ, the tests on the real core and the integration tests are what counts.
