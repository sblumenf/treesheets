# Milestone 5: formulas

Status: finished. TreeSheets' two ways to calculate are in the core: formula cells, whose
results are kept up to date after every change, and the program of a document (Program > Run).
Both were checked against the real TreeSheets, with no difference left unexplained. All checks
pass (`cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo test --workspace`): 257 tests (226 before) and 1 that only runs by hand, in 100 seconds.
`cargo check -p wombat-core --target wasm32-unknown-unknown` passes.

Milestone 4 (links and backlinks) was built at the same time on another branch. The two were
merged afterwards; "Together with milestone 4" below says what was checked where they meet.
With both, 292 tests pass.

## What the formula system is

TreeSheets has two mechanisms, and Wombat now has both.

**Formula cells.** A cell whose text starts with `=` shows the result of a formula. There are
no cell addresses like `B2`: a formula names a table by the text of the cell that holds it.

```
Costs                     a cell with the text "Costs" and a grid inside it
  Rent | 800
  Food | 250.5
=SUM(Costs)               shows 1050.5
=SUM(Costs) * 1.2         shows 1260.6
```

- `SUM`, `MIN`, `MAX`, `AVG` (or `AVERAGE`), `MEDIAN`, `COUNT` take the cells of the named
  grid that are numbers; with `TREE` in front (`TREESUM`) also everything in the grids inside.
- A name means **the nearest cell with that text that has a grid**: first the grid the formula
  is in is searched, level by level, then the one around it, and so on outwards. Two tables
  called "Costs" in two branches of a document each serve the formulas near them.
- A name on its own (`=Unit price * Quantity`) is the one number in its grid. Names with other
  characters than letters, digits, `_` and single spaces go in double quotes: `=SUM("Sales, 2025")`.
- `SUBSET(name, columns, rows)` is part of a grid, counted from 0: `=MAX(SUBSET(Sales, 0, 0-2))`,
  with ranges `0-3`, `3-`, `-4` and `-` for all. `TREESUBSET(name, columns, rows, levels)` also
  takes the same columns and rows of the grids inside. Either can take another `SUBSET` instead
  of a name.
- `+ - * /` and parentheses work on numbers; `&` joins texts; `'text'` is literal text. Text
  functions: `LEN`, `LEFT`, `RIGHT`, `MID`, `UPPER`, `LOWER`, `TRIM`, `SUBSTITUTE`.
- What goes wrong shows as `#NAME?` (no such table), `#VALUE!` (text where a number is needed,
  or not exactly one value), `#DIV/0!`, `#NUM!` (too large), `#ERROR!` (cannot be read),
  `#CYCLE!` (formulas that read each other in a circle), `#N/A` (a variable of the program
  that has not run yet). An error in a cell carries over to the formulas that read it.

**The program.** Cells can be marked as operation, variable or view. Running the program
works every grid through, row by row and then column by column, with one value in hand:

```
2 | + | 3 | (view)        after a run the view cell shows 5
5 | rate (assign)         the value in hand gets the name "rate"
rate (read) | inc | (view)   the view shows 6
```

A data cell becomes the value in hand; an operation (`+ - * / < > <= >= = == != <>`, `inc`,
`dec`, `neg`, `sum`, `min`, `max`, `avg`, `median`, `graph`, `transpose`, `if`) replaces it;
a view cell is overwritten with a copy of it, grid and all. Filling views is the only thing a
run changes. A formula can read a variable by name once the program has run.

## What was built

- **`crates/wombat-core/src/eval/`**, a module with no interface code, no global state and
  nothing that depends on the machine:
  - `num.rs`: reading and writing numbers and classing characters, written out instead of
    left to the system's libraries (decision A60);
  - `formula.rs`: reading and working out one formula;
  - `calc.rs`: `Calc`, which holds what every formula cell shows, works formulas out in
    TreeSheets' order, and brings results up to date after a change;
  - `run.rs`: the program, worked out on a private copy of the document.
- **The editor keeps results up to date.** `Editor` owns a `Calc` and gives it the change
  report of every command, undo and redo. `Editor::shown(cell)` is what a cell displays (for a
  formula cell its result), `Editor::recalculated()` the formula cells whose result the last
  change altered, `Editor::calc()` the rest (whether a result is an error, the variables, the
  report of the last run, how the last update was done).
- **Two commands** (40 now): `Run`, and `EnterText` ("typing into this cell has ended": the
  text, and whether the cell is a formula cell follows from it).
- **`SortRows` sorts by what cells show**, and the `.cts` importer finds the target of a link
  by what cells show, so a formula cell can be a link target (the two open ends of milestones
  2 and 3; the third, text commands on formula cells, is decision A65).
- **The command-line tool**: `wombat show` prints a formula cell as its formula `=` what it
  shows; `wombat new --from` makes cells that start with `=` formula cells; `wombat edit` has
  `enter CELL "text"` and `run`, and `changes` also lists what recalculated.
- **`referee/formulas/`**: the cases and what the real app answered (below).

The file format is unchanged. A formula cell is stored as its formula; results are worked out
after loading and never saved.

## Design (decisions A60 to A68, B50 to B57)

- **Where results live** (A61): in `Calc`, beside the document, never in it. In TreeSheets the
  result replaces the cell's text and the formula is kept beside it; that makes every piece of
  code that reads a text read a result. Wombat keeps the text as the formula and has one
  function for "what the cell shows".
- **Order** (A62): TreeSheets' order exactly, because with circles the order decides who says
  `#CYCLE!`. Not its recursion: formulas in progress are kept in a list, so a chain of 20,000
  formulas that each need the next (tested) costs no stack.
- **After a change** (A63): if only cells without a grid changed, the formulas that read them
  are worked out again, then those that read these, and nothing else. `Calc` remembers per
  formula which grids it read, not which cells. If anything changed that can alter what a name
  means (cells created, removed or moved, the text of a cell with a grid, anything about
  variables), or if a circle or the work limit is involved, everything is worked out again.
  This full fallback was chosen for correctness: names are positional, so a new row in one
  table can change what a formula elsewhere means.
- **Run** (A64): a command, one unit of undo, exact change report. A view cell keeps its ID;
  cells of a grid it receives are new. A run that changes nothing is nothing. Variables and
  the run's first failure are kept beside the results; like TreeSheets they are not saved and
  undo leaves them.
- **Names, not IDs** (A68): kept as in TreeSheets. See the proposal at the end.

## How it was checked against the real TreeSheets

All comparisons read recorded data; no test needs the app. Regenerating takes three minutes
(`referee/formulas/make_formulas`, with the app built at `_build/TreeSheets`).

| What | Compared | Mismatches |
| ---- | ---- | ---- |
| Every example of TreeSheets and the fixture, as loaded (`wombat-cts/tests/formulas.rs`, against `referee/golden/*.json`) | 38 documents, 8,198 cells, all 168 formula cells | 0 |
| The same after Program > Run, and the value the run returned (`*.run.txt`, `*.run-result.txt`) | all 18 documents with operation cells, 9,182 lines | 0 |
| Hand-written formulas: 517 formulas over 39 tables, and 27 documents about circles, order of errors, nearest names, Unicode names, number texts | 36 documents | 0 |
| Random formulas from a grammar (seed in `cases.py`): nested tables with duplicate names, every function, `SUBSET` nesting, text functions, deliberate syntax errors | 400 documents; with the hand-written ones 21,637 cells, 3,983 formula cells | 0 |
| Formula cells that have a grid themselves | 4 documents, 8 formula cells | 0 |
| Programs by hand: every operation on 38 pairs of texts, on rows, columns and grids, `if`, variables, views both ways, every failure | 62 documents | 0 |
| Random programs | 300 documents; with the hand-written ones 32,398 cells before and after the run, 362 returned values | 0 |
| Series of edits, the document compared after every step: change a number, rename a table, insert and delete rows and columns, delete a table, make and unmake formulas, sort, run, undo, redo | 38 series (8 by hand, 30 random), 309 steps, 13,045 cells, 3,848 formula cells | 0 |

In the series, sort and run were done in the real app by pressing the keys of the menu items
on its private display, the rest through its script functions. After every step the test also
checks that Wombat's results, kept up to date step by step, equal working everything out anew.

**Mismatches seen while building, and their causes:**

1. The median of `0x10`, `0`, `-0` came out as `0` where TreeSheets shows `-0` (and two cells
   that read it differed in consequence). Cause: Wombat sorted minus zero before zero;
   TreeSheets leaves equal numbers in their order. Fixed.
2. After a run, the tutorial's formula that reads a variable showed `18` where the golden data
   has `#N/A`. Cause: the golden data is made with the script function `ts.evaluate`, which
   throws the variables away; the menu item keeps them. Not a difference: the test compares
   without variables, and the series of edits (which press the menu item's key) show the `18`
   kind of result matching.
3. A formula cell marked as data showed its formula in Wombat and its last result in
   TreeSheets. A deliberate difference (B50); the test now does what TreeSheets does in
   Wombat's terms (it makes the result the text first).

Nothing else differed. The first full comparison of formula cells had 3 mismatches in 3,962
(all from cause 1), of programs none.

**Do the comparisons bite?** 26 deliberate breakages of the evaluator were tried, one at a
time: division by zero not an error; nine decimals instead of ten; the nearest name found
without regard to depth; a formula counting its own cell; `TREE` counting formulas inside; no
hexadecimal numbers; the wrong median; one text taken of several; errors not carried over;
circles named differently; no pass downwards in a run; `if` picking the other cell; an
all-data grid not run again; `sum` reading numbers strictly; readers of readers not
recalculated; a renamed table ignored; `SUBSET` one column short; upper case for ASCII only;
names not trimmed; a view keeping the kind of its value; tree readers forgotten; a failed
variable read giving nothing; assigned names not `#N/A`; a wrong number for unreadable text;
variables not kept for formulas; the no-break space counted as a space. **All 26 were caught
by the comparisons with the app's data.** The rule test "keeping up to date equals working
everything out" missed "readers of readers not recalculated" in one of its runs; its random
documents now always contain a chain of formulas, and it caught that breakage three times out
of three afterwards. The breakages were picked by hand: this shows the comparisons are not
empty, not that they are complete.

## Other tests

- **Rules on random input** (`tests/formulas_properties.rs`): any document is worked out
  without panic, within a time bound, to the same results every time, and its program runs or
  is refused; any text at all is a formula with some result; any text is read as a number or
  not, without panic; and for random sequences of commands (the 38 of milestone 3, plus
  entering numbers and formulas, changing kinds, sorting, running, undo, redo, groups): after
  every step the results equal a fresh calculation, the list of what recalculated is exact,
  and undoing everything gives the original bytes. 300 cases per run; run by hand with
  8,000 and, after the generator was strengthened, 3,000: no failure.
- **Examples of rules** (`tests/formulas.rs`, 13 tests): what recalculates when, circles,
  becoming and ceasing to be a formula cell, sorting by results, a run as one unit of undo,
  limits.
- A unit test of the number reader found a real fault before any comparison did: reading
  `0x1p-1074` (the smallest double, written in hexadecimal) overflowed an internal count.
  Fixed; such numbers are now in the referee cases and the random tests.

## Limits, and how hangs are prevented (A67)

| Limit | Value | Beyond it |
| ---- | ---- | ---- |
| Length of a formula | 4,096 code points | `#ERROR!` |
| Nesting of parentheses and calls in a formula | 64 | `#ERROR!` |
| Cells read by all formulas in one recalculation | 50,000,000 | `#LIMIT!` from there on |
| Cells visited and copied by one run | 20,000,000 | the command is refused |
| Nesting of a value in a run | 64 | the command is refused |
| What a run may leave | grids 32 deep, 700,000 cells | the command is refused |

Formulas that need each other are queued, not nested, so their number is no limit. Signs in
front of a number (`-----5`) are counted in a loop. Every part of the evaluator that calls
itself does so no deeper than one of the limits above or the depth of the document (32).
TreeSheets has none of these limits; it would run out of stack or time.

## Measurements

One document: 1,000 tables of ten numbers, ten formulas about each, one formula that sums
everything: 10,001 formula cells in 22,005 cells. Best of several, release build, on this
development container (debug build in brackets):

| | Time |
| ---- | ---- |
| Working out all formulas | 57 ms (309 ms) |
| After one changed number: 11 formulas worked out | 4.2 ms (33 ms), nearly all of it the one formula that reads the whole document |
| After an inserted row (everything is worked out again), with its undo | 91 ms (588 ms), so about 45 ms each way |
| A document of 101,001 cells without formulas: inserting a row and undoing it | 8 µs (60 µs), as before this milestone |

The test asserts generous bounds (500 ms, 50 ms, 1 s in release). The fallback of working
everything out after any structural change costs about 4.5 µs per formula here; a document
with a hundred thousand formulas would feel it at every inserted row.

## Known differences from TreeSheets

All are in `DECISIONS.md` section B (50 to 57) with reasons.

- A formula cell that stops being one shows its formula again, not its last result (B50).
- A formula cell that has a grid is named by its current result; TreeSheets goes by the result
  it showed last, which depends on what was calculated before (B51).
- The limits above (B52, B53).
- Where TreeSheets crashes (a variable assigned with nothing in hand), Wombat goes on (B53).
  Since the real app cannot survive it, this is not compared.
- A formula cell inside a variable's value counts by its result at the time of the run (B54).
- A run that changes nothing leaves no undo step (B55).
- Typing over a formula cell: one rule, `EnterText`; the plain text commands never change the
  kind (B57).
- On other systems TreeSheets itself differs (B56): in the plain `C` locale it knows only
  ASCII letters; on Windows it counts text in UTF-16 units. Wombat always behaves like
  TreeSheets on Linux in a UTF-8 locale. Numbers are the same everywhere in both (the decimal
  point is never taken from the locale).

## Together with milestone 4

- **Copying and moving cells between documents** (`PasteCells`, `AdoptCells`, `ReleaseCell`):
  a formula cell keeps its kind and formula and means, where it arrives, what the names mean
  there; results in both documents are brought up to date, also by undo and redo (a test by
  example). All three commands create or remove cells, so everything is worked out again.
- **The random test of the link index** (`tests/support/links.rs`, several documents, copies
  and moves between them, undo, redo) now also enters formulas and numbers and runs programs,
  and checks after every step, for every document, that the results equal a fresh
  calculation, next to its own rule that the link index equals a rebuilt one. A fixed run of
  250 cases: 3,001 commands, 858 copies, 701 moves, 1,918 formula steps; no drift of either.
  This is where the three commands are in a random test of formulas; the single-document
  test (`formulas_properties.rs`) does not have them.
- **What a link's target is shown as** (`links::place_shown`, used by `wombat links`,
  `backlinks` and `broken`): what the cell shows, for the cell and for the trail of cells
  around it, so a formula cell appears by its result. `links::place` still gives the stored
  text.
- **Imported links without a target** (`links::unknown_links`, `resolve_unknown`) now count a
  formula cell as a candidate by what it shows, the same rule as at import (A66; milestone 4
  had left formula cells out, as B15 said then).
- Both milestones' demos were run as written after the merge and print what the summaries say.

## Not done, doubtful, or different from the brief

- **What a view copies besides text** (colours, styles, column widths, notes, images) follows
  the C++ (`Cell::Clone`, `Cell::CloneStyleFrom`) but is not compared: the referee data for
  programs has texts, kinds and grid sizes only.
- **Hierarchify, flatten, collapse and hierarchy swap still go by the formula**, not by what a
  formula cell shows (A66). Sort does go by what cells show.
- **The link test rests on reading the C++**: `referee/formulas/links.cts` was saved by the
  real app, but no script function follows a link, so which cell TreeSheets goes to was not
  observed.
- **Everything is worked out again after any structural change** (measured above). Finer
  tracking of what a name depends on would avoid it and was not built.
- **`Editor::recalculated()` is a separate list**, not a field of the change report, so that
  the report's type did not change while milestone 4 was being built on it. Merging the two is
  a small change for later.
- **Variables are not saved and not undone.** After loading, or after undoing a run, formulas
  that read variables can show something else than before. This is TreeSheets' behaviour.
- **The 26 breakages and the grammar are mine**, and the same person wrote the evaluator and
  the cases. An independent review would be worth more than more cases.
- **Upper and lower case, and which characters are letters**, use the Rust standard library's
  Unicode tables with the single-character rule of the C library. Compared for a few dozen
  characters, not for all of Unicode.
- **`MEDIAN` of more than three numbers with both `0` and `-0`** around the middle may show
  the other zero than TreeSheets (B56).
- **Autocompletion of formulas** (`FormulaEvaluator::Completions`, `Names`) is interface
  help and was not ported.
- **`referee/formulas/golden/` is 1.3 MB** of generated text in the repository.

## Demo

From `wombat/`:

```sh
cargo build
cd /tmp && rm -f budget.wombat
printf 'Costs | =SUM(Costs) | =SUM(Costs) * 1.2\n  Rent | 800\n  Food | 250.5\nIncome | =SUM(Income) - SUM(Costs)\n  2000\n' > budget.txt
wombat=~/treesheets/wombat/target/debug/wombat      # wherever the build is
$wombat new budget.wombat --from budget.txt
$wombat show budget.wombat          # ... [2,1] "=SUM(Costs)" (formula) = "1050.5" ...

cat > edits.txt <<'END'
text /1,1/2,2 "300"
changes
enter /3,2 "='Left: ' & SUM(Income) - SUM(Costs)"
changes
text /1,1 "Kosten"
changes
undo
show
save
END
$wombat edit budget.wombat --script edits.txt
```

The first `changes` prints the changed cell and what recalculated:

```
changed /1,1/2,2 #...
recalculated /2,1 = "1100"
recalculated /3,1 = "1320"
recalculated /2,2 = "900"
```

the second `recalculated /3,2 = "Left: 900"`, the third (the table renamed) four formulas
that now show `#NAME?`. `wombat edit --help` lists `enter` and `run`; a program is run with a
`run` line, after which `changes` lists the filled views and the formulas that read variables.

## A proposal: references that survive renaming

Not built (A68). Formulas would stay text with names in them, as in TreeSheets, and the file
format would not change. One command would be added, "rename this table": it sets the text of
a cell that has a grid and, in the same unit of undo, rewrites the name in every formula in
which that name currently means that cell. `Calc` already knows which formulas read which
grid, so finding them costs nothing extra; the formula reader would have to report where in
the text each name stands. Afterwards the command checks that each rewritten formula still
finds the same cell (a nearer table with the new name could shadow it) and is refused if not.
It is cheap because nothing is stored and nothing else changes; it is safe because a formula
is only ever rewritten to mean what it meant.

## What the next milestones should know

- `Editor::shown(cell)` is the text a search index or an export should use for a formula
  cell; `cell.text` is its formula. `Editor::recalculated()` says which cells to index again.
- `wombat_core::eval::Calc::new(&document)` gives results for a document without an editor
  (the importer and `wombat show` use it).
- Adding a function to formulas: `FUNCTIONS` or `TEXT_FUNCTIONS` in `eval/formula.rs`, then
  cases in `referee/formulas/cases.py` if TreeSheets has it too.
- A command that should go by what cells show reads `tx.shown(cell)` instead of the cell's
  text (see `sort_rows`).
